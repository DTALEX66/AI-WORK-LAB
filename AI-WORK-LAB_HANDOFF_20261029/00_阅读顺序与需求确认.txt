AI-WORK-LAB 前端设计与本地后端融合任务包
版本：2026-10-29 R1

一、对本轮完整对话的理解

1. 把 WORK-LAB 与 DESIGN-LAB 合成一个产品和一个新仓库 AI-WORK-LAB，而不是把两个旧应用套进两个标签页。
2. 两仓已有能力、专业领域、规则中仍适用的约束、资源、数据、测试和历史来源要保留。重复内容可以合并，错误可以修复，旧实现可以被等价替代，但必须能追溯并证明行为没有无故减少。
3. 已冻结能力按实际原因处理：接入口、修复实现、补探测或扩展协议。删除冻结标签不能算实现。旧“仅辅助、不能执行”的产品边界可以在新仓按新需求扩展；隐私、权限与可恢复性仍保留。
4. 不强制全部使用 Agent。确定流程直接调用工具；开放任务连接成熟外部 Agent；不能自动连接时，支持复制提示词或导出任务包，由用户人工派发、导入结果并独立核验。
5. BOT 是一种交互和消息入口，可以后续增加；不因此先搭一套大型机器人平台、第二任务系统或第二知识系统。
6. 参考 AionUi、OpenHuman、OpenHands、DSH 等成熟项目的适用能力。OpenHuman 与 OpenHands 不同；参考界面或插件机制不等于换掉整个技术底座。
7. 最终具备自身迭代能力：接模型/执行器后可提出改进并修改自己的界面、后端、插件和技能，经过候选隔离、真实验证、版本切换与失败恢复。这是长期明确目标，本批复杂执行链延期。
8. 前端给 STITCH：先设计完整框架、重要状态与专业交互；后台未开发的能力也有合适入口，但必须显示待开发、待连接或待验证，不得假装能运行。
9. 后端给 ZCODE：在新仓本地工作分支完成既有能力迁入、融合、修复和基础闭环；复杂新增能力延期并完整登记。不得上传云端仓库，不通过其他途径上传项目或数据。
10. ZCODE 的“完成”只是待审计交付；之后由用户的本地 Codex 独立检查源码、原始命令结果和实际运行。审计通过仍不授权推送、发布或合并主分支。

二、交给谁、怎么交

明天给 STITCH：复制 01_STITCH_完整前端提示词.txt 全文。若支持附件，再给 04_原界面入口映射.csv、05_能力族分期.csv、08_前后端交接约定.json。附上你当前真实的 WORK/DESIGN 界面、SCREEN_12 与 DESIGN 全路径纠正版；没有这些附件时，STITCH 只能按提示词重建结构，不能宣称已核对旧画板。

给 ZCODE：复制 02_ZCODE_本地后端闭环提示词.txt 全文，并把整个任务包解压到非云同步的本地目录。在本地工具中打开 AI-WORK-LAB，绑定实际 WORK-LAB、DESIGN-LAB 来源路径。不要让它自行联网克隆仓库补文件。

ZCODE 汇报后给本地 Codex：复制 03_CODEX_独立审计提示词.txt 全文，提供 ZCODE 的本地工作目录、分支与审计证据目录。审计不是阅读 ZCODE 总结后签字，必须独立运行关键检查。

三、当前事实与限制

前一轮静态基线：WORK 2,632 项 Git 来源文件、DESIGN 4,035 项，合计 6,667 项；837 个来源条目存在模块、接口、视图与任务之间的重叠；67 组跨仓内容相同对象仅为去重候选。关键词能力族分类仍待复核，其中 8 个静态条目未分类。

这套资料不包含用户本地未提交增量、作品、权重、凭证或宿主安装状态。ZCODE 必须在本机补核；不得把上述数字写死成永远正确的通过条件。

本会话工作副本已切换到 integration/local-fusion-20261029。目标当前没有初始提交，所以 HEAD 只是新分支名称，尚无可用提交锚点。没有创建用户 Windows 上的分支，没有提交、推送或迁入业务代码。ZCODE 仍需在用户真正本地仓库核对并创建自己的工作分支。

已有盘点工具曾通过 11 项反例测试，这只说明盘点工具；不代表产品融合、桌面运行、宿主连接或自我迭代通过。

四、关于“只在本地执行”

本任务禁止 ZCODE 主动上传 Git 仓库、项目文件、作品、日志或任务包，也禁止云构建、远程执行、自动同步与远程遥测。代码、数据库、构建和验收产物都留在本地。

提示词和 Git pre-push hook 不是网络隔离。如果 ZCODE 本身使用云端模型，发送给模型的上下文仍可能离开本机。若要求源码和数据完全不外发，需要先使用本地模型/离线运行方式并配置实际出站隔离；当前任务包没有替你完成或验证这些设置。不能确认工具的自动索引/上传行为时，先停止读取敏感源码，报告实际限制。

五、阅读辅助文件

04_原界面入口映射.csv：56 个已登记旧入口的拟收敛位置；不是要求生成 56 个主菜单。另列补充入口，防止漏掉合成首页和别名。
05_能力族分期.csv：30 个能力族或复核集合的保留、实施和验收要求。
06_来源条目基线.csv：837 个来源条目的静态参考，不是功能完成清单。
07_来源文件基线.csv：6,667 项文件元数据；没有源码正文和私有作品。
08_前后端交接约定.json：前端展示、后端实现和审计共用的提议协议；尚未成为运行 API。
09_任务分期与验收.json：当前必做、条件实施、延期与通过条件。
10_现行设计任务映射.csv：50 项任务原始状态、标题及迁移处理建议。旧 DONE 不继承到新仓。
11_需求追溯.csv：把本轮用户明确要求与已知界面偏好分别列明。
12_来源基线.json：两仓历史固定提交；本地若已更新，应保留旧锚点并记录增量，不能强制回退。
13_文件校验.json：任务包自身文件 SHA-256，仅用于发现传输/编辑差异，不是独立验收证明。

本任务包只包含提示词、协议建议与来源元数据，不包含真实产品融合成果。前后端可按共同协议并行开展；STITCH 负责设计，ZCODE 负责本地后端，本地 Codex 负责独立审计。
