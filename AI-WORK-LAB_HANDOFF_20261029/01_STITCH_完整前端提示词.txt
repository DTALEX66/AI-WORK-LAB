你现在负责 AI-WORK-LAB 的完整桌面应用界面设计与可点击交互原型。请以资深产品设计师、交互设计师和熟悉工程交付的前端设计师协作，直接推进可审阅成果，不停留在泛泛建议。

【一、产品目标与本次职责】

AI-WORK-LAB 是将 WORK-LAB 与 DESIGN-LAB 深度融合后的一个个人桌面工作台，面向设计师和只懂少量编程的用户。它统一项目与运行状态、任务与结果、专业设计辅助、知识与方案、外部 Agent/软件连接，并为未来自身开发迭代保留入口。

用户既需要“看清项目怎么样”，也需要“把任务交给合适的工具完成”。确定流程直接调用工具，开放任务才用成熟 Agent。无法自动派发时，用户能复制提示词或导出任务包，交给外部软件，再导入结果。不要把产品缩成聊天客户端，也不要把它设计成程序员监控后台或强制流程编辑器。

你本次负责前端信息架构、设计系统、完整关键页面、组件和状态、可点击演示及工程交接。不要改后端、安装模型、连接真实账号、访问私有作品或执行 Agent。未接入后端的原型数据必须明确为演示。

最终只有一个应用外壳、一套导航、一套设置、一个项目上下文。WORK 和 DESIGN 是内部能力域，不保留两个独立品牌首页和两套互相跳转的产品。

【二、先读取既有成果，再设计】

如当前 STITCH 项目或用户附件中存在以下成果，先查看并建立入口与组件对应关系：
1. WORK-LAB 已确认的 SCREEN_12 紧凑结构、“我的工具”层级、项目列表和项目概览。
2. DESIGN-LAB 综合交互原型全路径纠正版：D01 需求、D02 方案工作台、D04 我的方案；材料准备、按需展开与带走；知识复用与可控状态切换。
3. 真实当前截图、路由和组件。如附带 04_原界面入口映射.csv、05_能力族分期.csv、08_前后端交接约定.json，以其中的来源和状态约定辅助对账。

没有访问到的旧画板、截图或代码不得声称已读取。资料不足时按本提示词完成统一结构和关键交互，另列待核对项；不要自行补造“旧版截图”。保留已经明确认可的结构，不因为新仓就彻底换成另一套通用模板。

【三、视觉方向】

主方向是精致、紧凑、冷色的桌面软件，具有克制的 Apple 风格、清晰层级和适量玻璃质感。默认深色；同步建立珍珠白与冷色科技主题的 token，而不是制作三套互不兼容的布局。不能偏暖、发黄、奶油色。

玻璃只用于顶栏、浮层、HUD 和少量层级过渡。正文、表单和阅读区域要稳定、易读，避免整屏透明、满屏发光和多层卡片嵌套。科技主题不是把应用做成游戏驾驶舱，不照搬 AAOS 的星空知识舱，也不加入 ASTRYN 人物、桌宠或独立聊天伴侣。

用真实软件结构表达专业性：紧凑列表、明确的选中态、短状态标签、合理的留白、适量预览图和可展开详情。减少长说明和巨大 KPI 卡片。图形化应帮助理解，不用环形仪表、装饰性流程图或复杂连线替代实际信息。

顶部是应用内的系统菜单栏，提供文件、项目、任务、视图、工具、帮助等简洁菜单和下级弹层；它不是网页营销导航，也不是假装控制 Windows/macOS 系统。窗口控制区域按桌面应用留出适配空间。

若当前已有 W/星形连接标志，优先保留可用资产；缺少时用简洁文字标识，不另造品牌视觉系统。界面中文为主，工具/API/模型名保留原文。

【四、统一导航与布局】

建议一级导航不超过六项：总览、项目、任务、设计、知识、工具。设置通过固定齿轮入口进入。全局搜索和项目切换固定可达。能力目录、连接管理、模型与自身迭代入口放在工具区的合适层级，不把全部未来能力铺成一级菜单。

采用一个 SPA 外壳与共享状态。左侧紧凑导航，中间当前工作区；右侧详情抽屉按需打开，不强制每页常驻第二个窗口。任务详情、工具能力、设计方案、证据和权限确认优先复用抽屉/侧面板。不要复制多份侧栏、项目选择或全局状态。

项目、工作区、搜索条件、展开状态、当前方案修订和目标组合在视图切换时保留。返回上一页应恢复位置；刷新后仅恢复适合保存的演示状态，不能存真实凭证。

1920×1080 为主要展示画幅，同时校验 1440×900 与 1280×800。遵从实际容器宽高重排，不能靠整体缩放截图或固定绝对定位撑满。手机端暂不进入本期。

【五、核心页面与交互】

F01 总览
- 首屏看见项目列表/最近项目、待处理事项、正在进行的任务和“我的工具”紧凑列表。
- 项目以短行或紧凑条目呈现：名称、总体状态、最需要注意的一件事、最近更新。点击进入项目详情。
- 我的工具展示图标、工具名、连接/探测状态、关联项目、最后检查时间；常用入口是使用方法、提示词与规则、常见问题；高级选项折叠。
- 没有后端数据时显示未连接/无记录和下一步；演示内容用一个持续可见的“演示数据”标记，不能全部绿灯。

F02 项目与项目详情
- 项目列表可搜索、筛选、切换；项目详情显示概况、当前阻塞、任务、相关工具、近期变更与必要的资源/用量。
- 主视图面向普通用户显示项目级进展。日志、堆栈、构建细节、审计区间放二级详情。
- 可使用“AAOS、AI-WORK-LAB、示例设计项目”作为演示对象，但标记演示；不能把已合并的 WORK/DESIGN 两个旧产品永久保留为两个主应用。
- 用量未知显示“未取得”，不能显示费用 0 或“正常”掩盖缺数据。历史时间与当前时间明确区分。

F03 任务与执行详情
- 同时支持普通任务、设计任务、修复任务、未来自身开发任务，共用任务列表和详情框架。
- 展示目标、输入、交付物、执行方式、尝试次数、当前状态和下一可执行动作。默认隐藏工程字段。
- 人工路径完整可演示：创建任务→整理输入与验收→预览任务包→复制提示词/导出→用户声明已交接→等待结果→导入结果→结果待核验→核验结论。
- “已复制”只表示本地复制；“用户声明已交接”不表示外部 Agent 确认收到；“结果已导入”不表示通过。
- 自动路径是后续能力：选择已探测执行器→确认范围→派发→运行事件/等待输入/等待权限→结果回收→独立核验。未接通时展示原因与人工替代，不用假进度条冒充真实运行。
- 断连进入“执行状态待确认”，提供对账/查询入口；不能自动重发造成重复编辑。取消中与已取消分别显示。
- 每次重试是新的尝试，旧结果和失败原因仍能查看。
- 设计结果增加作品预览、版本比较、预检和专业确认。技术检查通过不能自动写“设计通过”。

F04 设计工作台
- 继承 D01/D02/D04 的有效交互，整合成可自由进入的输入、分析与方案、我的方案，不强迫线性向导。
- 允许文本、图像、参考文件及已有方案引用；按领域、目标、输出规格组织信息。音频、视频、三维等输入若未实现，以待接入格式显示，不允许假装已解析。
- 材料准备、参考拆解、创意方向、结构重构、提示词、制作建议、质量检查与交付要求按需展开。
- 方案详情支持修订、复制、导出和目标组合。目标组合明确区分软件×模型×接入方式；“已选择目标”不等于“目标已连接可执行”。
- 设计方案、生成任务包和真实产物是不同对象，分别提供清晰入口，避免把提示词导出写成作品生成完成。
- 保留 13 个现存专业领域的入口/检索：品牌、平面、视觉、UI/UX、产品 UI、电商、包装、动效、视频、音频、三维、空间、小游戏。短视频、短剧、漫剧等作为相关领域内的任务类型，不自动生成新的独立系统。
- 真人评审、深度图层重建、跨软件往返、模型生成等复杂新增执行能力可显示延期，保留可读说明和接入位置，不做伪可运行入口。

F05 知识与方案
- 统一检索入口，区分设计知识、提示词、制作规范、已验证维护方案、候选经验。
- 搜索和内容列表是主结构，标签与筛选紧凑。详情展示来源、适用范围、修订、推荐版本、信任状态与关联项目/任务。
- 保留短中文检索、修订冲突和空结果状态。知识收藏不等于已验证，外部 Agent 的记忆不直接同步成产品权威知识。
- 选中知识可带入设计方案或任务包，形成有来源的引用；不另做 AAOS 完整知识库、双链图谱或企业协作系统。

F06 工具、Agent、软件、模型与接口
- 提供“我的工具/连接”“可用能力”“模型与目标组合”三个清楚的视图层级。
- 区分工具/软件、执行器、模型服务与接入方式。用户能看懂：使用哪个工具、需要什么模型或账号、当前缺什么。
- 只展示已知版本/状态，未知显示未知。不要把历史 Qoder 版本、某模型名或当前机器安装假设写死。
- API 模型、本地模型、工具原生订阅的入口位置清楚；默认不要求用户把所有工具的密钥集中交给 AI-WORK-LAB。
- 原生认证由工具管理。设置中给出打开原生配置或查看状态的设计位置，不显示真实密钥、会话和私人路径。
- AionUi 可参考发现、会话、等待权限和结果展示；不照搬其完整壳、执行后端或 Team Mode。BOT 渠道不是首期必须配置项。

F07 能力目录与未来能力
- 所有能力按领域、目标和可用条件检索；默认突出现在能用的能力，用户可切换查看全部与延期能力。
- 同时显示三个维度：实现情况、验证情况、连接情况。不能用单一红绿灯合并三者。
- 最少有：待开发、已实现未验证、待连接、待授权、可使用、暂不可用、延期。状态显示文字和图标，不仅靠颜色。
- 能力详情说明当前能做什么、缺少什么、替代入口、来源和最后验证时间。延期项允许查看/收藏；真实执行按钮禁用并给原因。
- 前端完整展示框架与后端完成度分开：蓝图的详情可点击，不代表其中动作能调用。

F08 设置与本地模式
- 通用、外观、文件与数据位置、隐私与采集、工具连接、模型服务、诊断与恢复按用户语言组织。
- 清楚区分本机文件操作、向模型发送内容、向外部执行器派发、向云端仓库发布四类行为。
- 本轮默认本地模式：不上传云端仓库、不自动派发外部任务。演示中展示规则及“需要连接/授权”，不能宣称已实现系统级断网。
- 凭证始终掩码；真实会话内容和私人材料不进入演示。不可恢复的清理不放在默认快捷动作。

F09 迭代实验室
- 保留未来“修改应用自己”的完整信息位置：改进需求、候选版本、允许修改范围、执行者、代码/界面差异、测试结果、待审计、可升级、恢复记录。
- 分开技能与知识更新、插件更新、前后端源码更新。
- 当前主要是框架设计和延期状态。按钮名称采用“创建改进任务”“查看候选”“查看检查”“准备升级”“恢复版本”，不要无条件提供“一键无限自我进化”。
- 只有通过独立检查且符合授权时才设计可用的版本切换动作；不让 Agent 的自述变成批准自己的凭据。
- 不把普通用户首页变成代码编辑器；工程详情按需展开。

F10 HUD 与共用抽屉
- HUD 是同一应用的轻量浮层/紧凑模式，显示当前项目、运行任务、一个关键告警和返回主界面的动作，不是一套独立产品。
- HUD 不与主界面重复渲染所有表格和动画，关闭后不后台持续刷图。
- 共用抽屉包括任务详情、权限确认、结果导入、工具能力、证据与错误；确认展示具体对象、动作和范围，不用企业“审批流”措辞。

【六、前后端状态与交接】

如有 08_前后端交接约定.json，请遵守其中实体和状态；无附件时至少使用以下约定。它们是目标协议，不是声称 API 已存在。

Task、Attempt、Result、Verification 分开；Project 绑定上下文；DesignPlan 与 TargetProfile 保留修订；Artifact 指向输入/输出；Capability 描述能力条件；Connection 描述连接。

任务展示需覆盖：草稿、就绪、等待交接、用户声明已交接、排队、运行、等待输入、等待权限、断连待确认、取消中、已取消、结果已收到、核验中、通过、未通过。实现内部若复用旧状态名，应提供对应表，不能复制第二状态机。

data_origin 区分 demo 与 live，验证状态未知不能等于通过。可用性由实现、验证、依赖、连接与授权条件共同决定。原型用 demo 数据驱动，不伪造 connected=true 或 verified=true 来美化画面。

服务未连接、加载、空列表、离线、依赖缺失、无权限、输入错误、版本冲突、超时、断连、部分成功、失败与重试均有清晰状态面。按钮禁用应显示原因；需要用户操作时给一个明确下一步。

【七、必须走通的演示旅程】

J1 总览→项目→查看阻塞→相关工具→使用方法→返回原项目。
J2 创建普通任务→导出人工任务包→声明交接→导入演示结果→独立核验显示未完成/待核验，而非自动成功。
J3 设计输入→分析/方案→选目标组合→复制提示词或导出→我的方案→查看修订。
J4 搜索一条设计知识→查看来源与修订→引用进方案→返回后条件保留。
J5 选择未连接 Agent→查看缺失条件→切换人工交接，保留同一任务与新尝试关系。
J6 模拟运行等待权限/输入、断连、失败与取消，逐一查看对应状态与可执行动作。
J7 能力目录→查看延期能力→阅读依赖与未来位置；真实执行保持禁用。
J8 迭代实验室→查看候选差异与待审计状态→恢复记录；不能把演示切换说成真实升级。
J9 主界面→HUD→返回，当前项目和筛选不丢失。

【八、交付物与验收】

1. 一个统一的桌面应用设计与可点击原型，包含上述主页面、必要详情与状态，不交一组互不连通的海报。
2. 一份信息架构与旧入口收敛映射；将同类功能归入页内标签/抽屉/高级区。若有 04 文件，56 项必须全部有去向，团队协作旧入口标记范围外保留来源。
3. 设计系统：颜色/字体/间距/圆角/阴影/玻璃强度/状态 token；深色主主题完整，珍珠白与冷色科技主题共享布局。
4. 关键页面 1920×1080 截图及 1440×900、1280×800 自适应检查。没有实际导出对应像素时，不在文件名里虚称 4K。
5. 组件与交互说明：导航、项目行、工具行、任务状态、方案修订、能力条目、抽屉、弹窗、Toast、表单错误、空态、骨架屏。
6. 工程交接：页面/路由、组件、所需数据字段、动作与状态条件、未实现依赖、演示数据集。如工具支持源码导出，提供可复用结构和 token；不声称已完成 React/Tauri 集成。
7. 无横向页面溢出、中文截断、遮挡、死链接；键盘可到达主要操作，焦点清楚，关闭浮层返回触发位置；减少动态效果模式可用。避免为质感牺牲文字对比和阅读。
8. 长列表采用分页/虚拟化的设计约束，详情按需加载，非活动视图不持续轮询。动效用于状态过渡，不持续满屏动画。

开始时先用简短清单确认实际读到的旧成果与缺失项，然后直接制作一个主方向并持续补齐交互。不要反复让我选择三个完全不同的模板。最后逐项汇报“设计完成、原型可点、演示数据、真实后端未连接、待补资料”，不得把设计完成说成产品已实现。
