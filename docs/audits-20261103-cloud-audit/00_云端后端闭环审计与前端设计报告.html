3. 新发现的可复现问题

P1 · N01 新克隆默认启动缺工作区初始化

事实：README默认入口 python -m backend 因 owning project marker is missing 退出；显式准备合成工作区后可以启动。

位置：backend/__main__.py:24,36；backend/app.py:40–43；domains/design/design_lab/runtime/paths.py:240–243

影响：用户首次打开与新前端连接受阻；测试fixture的成功启动不能覆盖默认启动缺口。

修复与验收：提供安全初始化/选择工作区契约和可运行命令，不删除目录拥有权校验、不静默写任意目录。

交付证据：evidence/default-startup.json

P1 · N02 任务列表加项目筛选返回404

事实：无参数GET /api/v1/tasks为200；同一服务带合法project_id为404。exact路由缺path_only，查询handler无法抵达。

位置：backend/v1.py:166,538–543；domains/design/design_lab/http_service.py:592

影响：项目任务列表接线失败，UI若吞错会误报没有任务。

修复与验收：修正路径/查询匹配，验证两个项目隔离、未知ID和参数错误的真实HTTP行为。

交付证据：evidence/http-probes.json#tasks_project_query

P1 · N03 顶层专业确认要求被静默忽略

事实：POST任务professional_required=true放顶层时201却返回0；当前实现仅读acceptance内字段。

位置：backend/v1.py:545–557

影响：调用方明确提出的专业确认要求可能丢失。没有证明正确嵌套配置下真人门被绕过。

修复与验收：规范字段并拒绝歧义/冲突/错误类型；创建后读回，要求专业确认的任务无批准始终不完成。

交付证据：evidence/http-probes.json#top_level_professional_required

P2 · N04 非法项目source被自动当成design

事实：source=not-a-supported-source返回201并创建design项目。

位置：backend/v1.py:365–395

影响：错误输入静默写入错误域，污染项目上下文与映射。

修复与验收：显式枚举校验；拒绝后统一库和设计域均无残留。

交付证据：evidence/http-probes.json#unknown_project_source

P2 · N05 探针和测试硬编码Windows路径

事实：核心有1项Windows盘符匹配断言在Linux失败；迁移命令初次21项无法启动，增加审计解释器桥后相关29项通过。

位置：tests/unified/test_v02_surface.py；tests/unified/test_v12_data_migration.py；scripts/boot_probe.py

影响：新克隆/不同平台难以复验，不能把环境故障直接算业务功能失效或无条件忽略。

修复与验收：明确平台矩阵、使用当前解释器与平台适当路径断言；不删测试或skip换绿。

交付证据：三份sanitized JUnit及独立节点CSV

N01–N04是实际入口或请求处理问题；N05主要是跨平台复验问题。本次未修改这些实现。它们与仓库此前F01–F10的修复登记分开编号，避免把新问题误说成旧审计完全未修。
