### 1. 项目要完成什么

AAOS 的目标是把同一批知识贯穿两条真实闭环：

- **人的学习**：多格式资料 → 来源与证据 → 人工接受的知识 → 检索 → 课程 → 作答与评估 → FSRS 复习与 Mastery → 重启后读回。
- **机器纠错**：同一知识 → 真实本地模型任务 → 人工发现实际错误 → Correction → Retest → 重启后读回。

最后还要通过备份恢复、旧数据隔离迁移、正式 Candidate 验收和 Green 授权替换。

### 2. 必须保持的边界

| 范围 | 已确定的要求 |

| 旧技术 | React/Tauri/legacy Python 仅作恢复、迁移与参考 |
| 状态管理 | 沿用 R6 TaskPack、M0 overlay、R6-EXECUTION、R6-STATE |
| 模型治理 | WORK-LAB 管共享模型、Runtime、Provider、健康与基准测试 |
| AAOS 数据 | Source、Evidence、Knowledge、向量索引、学习与纠错数据由 AAOS 管 |
| 真实性 | 不允许假进度、假 KPI、mock success、静默换模型 |
| 发布 | Release 保持 FROZEN；Green 替换和 Release 解冻分别需要 Owner 决策 |

**执行器与模型不必锁死，角色职责和 single writer 边界必须保持。**

### 6. 多格式与共享模型怎么分工

**格式顺序：**

- 首批：TXT、MD、文本 PDF、扫描 PDF、HTML、图片。
- 紧随：DOCX、音频；音频必须在最终多格式闭环前完成真实测试。
- XLSX/PPTX：已有适配器成熟时纳入，不阻塞 M0。

所有格式统一保留：**Source 身份、SHA-256、解析器/Provider 版本、Transform、结构、Anchor、质量/损失与来源记录**。

| WORK-LAB 提供 | AAOS 负责 |
|---|---|
| `local.fast.default`、`local.deep.default` | 模型任务、知识绑定、结果、人工纠错 |
| `local.embedding.default`、`local.reranker.default` | 向量数据、索引、检索结果与证据定位 |
| `local.ocr.default`、`local.asr.default` | 输入资料、转换记录、业务质量与证据锚点 |
| Runtime、模型文件、健康、重启与回退 | 明确显示 unavailable/degraded/offline，保存 provenance |

Provider 未就绪时，应记录明确阻塞或降级，继续推进不依赖它的 UI/Core 工作；不另下载模型副本。

### 7. 清理任务如何处理

2. 核对引用、生成方、使用方、进程锁与恢复方式。
3. 分类为保留、归档、可重建删除、Owner 授权删除、禁止删除。
4. 根据精确路径和证据执行获准清理。

**“仓库 100+GB、Green 数十 GB”是附件中的待核验描述；当前可回收空间仍是 UNKNOWN。** 用户数据、共享模型、资料库、未提交工作和唯一恢复证据必须保护。
