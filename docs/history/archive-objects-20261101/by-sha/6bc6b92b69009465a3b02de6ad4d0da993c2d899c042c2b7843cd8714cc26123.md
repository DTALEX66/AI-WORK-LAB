## 3. “每日 GitHub AI 项目筛选表”字段

每天筛 5–10 个项目，建议固定这些字段：

| 字段 | 说明 |
|---|---|
| 日期 | 例如 2026-06-29 |
| 项目名 | owner/repo |
| 项目类型 | RAG / Agent / MCP / Coding / Crawler / Parser / VectorDB |
| 当前 Star | 总热度 |
| 近期增长 | 今日/7天/30天新增 Star |
| 最近 Release | 判断维护活跃度 |
| 最近 Commit | 判断是否还活着 |
| License | MIT / Apache / BSD / AGPL / GPL / Custom / Unknown |
| 是否适合 Codex | 是 / 否 / 只适合参考 |
| 是否省 Token | 是否能压缩上下文、缓存、摘要、路由 |
| 是否本地可跑 | Windows / Docker / Python / Node |
| 可借鉴模块 | 具体到模块，不写空话 |
| 风险 | 许可证、依赖、执行代码、密钥、误删 |
| 今日建议 | 入库 / 跟踪 / 深挖 / 放弃 |

评分公式可以这样：

```text
daily_score =
  0.25 * star_growth
+ 0.20 * codex_fit
+ 0.15 * license_safety
+ 0.15 * local_first_fit
+ 0.10 * token_saving_value
+ 0.10 * recent_activity
+ 0.05 * documentation_quality
```

原因：

```text
1. Star 极高但项目出现时间/增长速度需要复核
2. 名称、描述大量贴近 AI Agent / Claude Code / Codex 热点
3. 部分项目不像传统长期维护型工程项目

```

这里要分清：

```text
仓库存在 ≠ 项目可靠
Star 高 ≠ 质量高
能打开 GitHub ≠ 许可证安全
榜单出现 ≠ 适合纳入你的系统
```
