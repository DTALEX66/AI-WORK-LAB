能，但要分清 **MiniMax Design 的“本地模型”是哪一层**。

### 1. 图像 / 工作流模型：可以本地跑

MiniMax 官方最近已经公开了 **MiniMax Design Plugin for ComfyUI**。官方仓库明确写的是：

> 基于 ComfyUI，为 MiniMax 创作产品提供「可视化工作流编辑与本地推理能力」。

它的结构就是：

`MiniMax Design → ComfyUI Frontend → ComfyUI Python Backend → 本地模型`

也就是说，**本地 ComfyUI 模型、工作流、本地 GPU 推理这条路线是官方正在做的**。citeturn573940view0turn355972view0

所以像这一类理论上属于它的本地推理层：

- FLUX / SDXL / 各种图像模型
- ControlNet
- LoRA
- IP-Adapter
- 放大 / 修复 / 抠图模型
- ComfyUI 自定义节点
- 部分本地视频模型
- 自己制作的 ComfyUI Workflow

这其实对你的 **DESIGN-LAB** 很重要。

---

### 2. 但是你问的如果是「Ollama / LM Studio 本地大语言模型」：目前不是直接插上就行

截至我现在查到的 **2026 年 9 月 21 日官方公开资料**，MiniMax Design **没有明确公开一个类似这样的设置入口**：

```text
Provider: OpenAI Compatible
Base URL: http://127.0.0.1:11434/v1
Model: qwen...
API Key: xxx
```

我也检查了 MiniMax Design 官方开源的 ComfyUI 插件，目前公开内容里没有看到 `Ollama` 或通用 `OpenAI-compatible LLM Provider` 的配置说明。citeturn573940view1turn573940view2

也就是说：

| 能力 | MiniMax Design 当前情况 |
|---|---|
| MiniMax 自家云端 Agent 模型 | ✅ |
| MiniMax 云端图像/视频模型 | ✅ |
| ComfyUI 本地推理 | ✅ 官方已经开放 |
| ComfyUI 本地视觉模型 | ✅ |
| 自定义 ComfyUI Workflow | ✅/正在完善 |
| Ollama 本地 LLM | ⚠️ 暂未看到 Design 官方直接入口 |
| LM Studio 本地 LLM | ⚠️ 暂未看到 Design 官方直接入口 |
| vLLM 本地 LLM | ⚠️ Design 暂无公开直连配置 |
| 任意 OpenAI-compatible API | ⚠️ Design 暂无公开 BYOK Provider 说明 |

所以不能简单说“MiniMax Design 不支持本地模型”。

更准确的是：

> **它已经支持/正在支持 ComfyUI 型的本地推理，但目前没有证据表明 MiniMax Design 主 Agent 可以像 Open WebUI、Hermes 那样直接换成 Ollama/LM Studio 本地 LLM。**

---

### 3. 有意思的是：MiniMax Code 已经支持本地模型

MiniMax 自己的另一个产品 **MiniMax Code** 已经正式支持：

- 自定义 Provider
- OpenAI Completions
- OpenAI Responses
- Anthropic Messages
- `base-url`
- self-hosted endpoint
- local server

官方甚至直接给出了本地服务器示例：

```text
--base-url http://localhost:8080/v1
--model local-model
```

citeturn265479search0turn265479search2

这意味着技术上 MiniMax **完全不是做不到**。

更像是：

```text
MiniMax Code
     ↓
已经开放 Model Provider 层
     ↓
Ollama / vLLM / LM Studio / 中转 API
```

而 MiniMax Design 目前更偏：

```text
              MiniMax 云 Agent
                    ↓
             MiniMax Design
                    ↓
        ┌───────────┴───────────┐
      云模型                 ComfyUI
                               ↓
                         本地视觉模型
```

---

## 4. 对你的 DESIGN-LAB，我反而不建议死等 MiniMax Design 开放本地 LLM

可以直接做成：

```text
                   DESIGN-LAB
                       │
             ┌─────────┴─────────┐
             │                   │
        Brain / Router       Design Executor
             │                   │
   ┌─────────┼────────┐      MiniMax Design
   │         │        │            │
Ollama    云端API   GPT/DS       ComfyUI
LM Studio                        │
vLLM                       本地视觉模型
   │
本地 LLM
```

也就是说：

**MiniMax Design 不要当“大脑”。**

把它定位成：

> **AI 设计执行器 + Canvas + Agent UI + Adobe/ComfyUI 操作层**

而 DESIGN-LAB 自己负责：

> **模型路由、规划、记忆、知识库、任务拆解、模型选择。**

这样以后即使 MiniMax Design 换掉，你的整个系统也不会被绑死。

---

而且这里出现了一个对我们之前 **DESIGN-LAB 架构判断非常重要的新信息**：

**MiniMax Design 官方已经把 ComfyUI Plugin 源码放出来了，而且明确包含本地推理后端。** citeturn573940view0

这意味着我们上次讨论的：

**DESIGN-LAB → MiniMax Design → Photoshop / Adobe → ComfyUI → 本地模型**

这条链已经比之前更现实了。

你这台 **RTX 5060 8GB** 不适合硬跑巨型视觉/LLM，但很适合把 **小型本地 LLM + 量化视觉模型 + ComfyUI** 当成本地免费执行层，再把重任务自动路由到云端。memcite

如果你愿意，我下一步可以直接把 **MiniMax Design 最新开源仓库整个拆开审计**，看看能不能通过修改 Provider/Backend，**强行给它接入 Ollama、LM Studio、OpenRouter、你自己的 WORK-LAB Router**，这对 DESIGN-LAB 的价值会比单纯研究它界面大得多。

# 二、MiniMax Design 本身怎么部署

这里有一个很重要的区别。

MiniMax Design **完整桌面客户端并没有完整开源**。

官方目前开放的是：

```text
MiniMax Design Plugin for ComfyUI
├─ frontend
└─ backend
```

而且官方明确说：

> 仓库只是自动同步的源码快照，构建产物、依赖、模型文件、缓存、运行数据、内部部署工具都没有包含。

所以不要试图直接拿那个 GitHub 仓库：

```text
git clone
→ npm install
→ python xxx
→ 自己编译完整 MiniMax Design
```

这不是目前正确的安装方式。citeturn998674view0turn181835view0

- macOS 13+
- 桌面客户端
- 本地文件 Asset Center

```text

     ▼

     │
     ▼
```

这是 ComfyUI 最适合 DESIGN-LAB 的地方。

```text

```

# 八、MiniMax Design 放在哪一层？

这是这次最关键的判断。

不要把：
