# 一、增强模块重新定义

现在的增强模块不要叫“配置管理”。

应该升级为：

# WORK-LAB Governance Layer

即：

> 用户工作流治理层

负责管理：

- 用户意志
- 工作规范
- 项目规则
- AI执行边界
- 能力扩展
- 审计证据

不负责：

- 第三方软件本身


---

# 二、核心原则：三层隔离

未来所有配置必须分三类。

---

# Layer 1：用户资产（必须永久保护）

这是 WORK-LAB 的核心价值。

必须进入 Git 管理。

例如：

```
/governance

├── rules
│   ├── coding-rules.yaml
│   ├── design-rules.yaml
│   ├── security-rules.yaml
│
├── skills
│   ├── github-audit
│   ├── ui-review
│   ├── architecture-review
│
├── policies
│   ├── agent-boundary.yaml
│   ├── model-policy.yaml
│
├── workflows
│   ├── software-dev.yaml
│   ├── design-flow.yaml
│
├── schemas
│
└── contracts
```

这些属于：

## User Intent Layer

必须保护。


例如：

### AI执行规则

```
禁止:
- 自动删除
- 自动发布
- 自动merge

必须:
- 提交审计
- 保留证据
- 生成hash
```

这种东西不能被 OpenAI/Cursor/Hermes 更新覆盖。


---

# Layer 2：适配层（可更新）

这个非常重要。

不要直接绑定平台。

错误：

```
WORK-LAB
 |
 └── Cursor Config
 └── Claude Config
 └── Hermes Config
```

这样死。


应该：

```
WORK-LAB Core

        |
        |
 Adapter Layer

        |
 ----------------
 |      |        |
Hermes Cursor Codex
```

例如：

```
adapters/

├── hermes.yaml
├── cursor.yaml
├── codex.yaml
├── vscode.yaml
```

里面只保存：

- 映射关系
- 能力检测
- 参数转换


例如：

```
WORKLAB skill:

code-review

转换:

Cursor:
.rules

Codex:
instructions.md

Hermes:
skill.json
```

---

# Layer 3：运行缓存（禁止进入Git）

例如：

```
runtime/

├── logs
├── cache
├── tokens
├── sessions
├── temp
├── model-history
```

这些不要管理。

否则：

1. 仓库污染
2. 泄露风险
3. 无法升级

# 四、官方更新覆盖问题怎么解决？

采用：

# Immutable Core + Mutable Runtime


结构：

```
WORK-LAB

core/
    用户定义
    永久规则


adapter/
    平台转换


runtime/
    当前环境


snapshot/
    当前状态快照

```

升级：

例如 Cursor 更新：

以前：

```
Cursor更新
 ↓
覆盖配置
 ↓
WORK-LAB失效
```


以后：

```
Cursor更新

 ↓

检测变化

 ↓

Adapter重新生成

 ↓

用户规则重新注入

```

↓
