# Design System: WORK-LAB 项目级轻量界面
日期：2026-10-24
适用：桌面主窗口、详情抽屉、独立 HUD；与同目录完整提示词配套。
性质：产品设计目标，未代表代码实现或真实运行状态。

## 1. Visual Theme & Atmosphere
安静、易读、日常应用密度。密度 4/10，布局变化 3/10，动效 1/10。
用户是使用外部 AI 工具开发软件的普通项目所有者。
主体是软件项目整体进展、问题、工具使用辅助和可复用经验。不得改成媒体制作项目或 Agent 控制台。
首页不展示项目内部阶段。图形解释问题、方法、结果与项目间关系。

## 2. Color Palette & Roles
- Canvas Charcoal #10141A：全局背景。
- Shell Slate #171D25：侧栏和窗口外壳。
- Content Surface #1C2430：必要内容分组。
- Primary Ink #E8EDF3：主要文字。
- Secondary Ink #A6B0BE：摘要与时间。
- Quiet Border #303A46：少量结构分隔。
- Restrained Cyan #40B6C7：唯一品牌强调色，主要操作与选中。
琥珀、红色仅用于语义状态，配文字。不得用颜色单独表达结论。
避免纯黑、霓虹、发光边、紫蓝渐变。玻璃限外壳、HUD、浮层；正文稳定可读。

## 3. Typography Rules
Segoe UI、Microsoft YaHei UI、系统无衬线字体。
页面标题 22–24px，区块标题 16–18px，正文 14–16px，辅助文字 12–13px。
用字重和颜色建立层级，不使用巨型标题；不额外下载展示字体。
图标配中文标签，不以英文缩写或工程枚举装饰界面。

## 4. Component Stylings
按钮：一个区域只突出必要主要操作，青色实底或低对比次级按钮。键盘焦点清楚，无外发光。
卡片：项目卡片表达独立项目，圆角 10–14px；其他内容尽量以留白和轻分隔组织，避免套卡片。
控件：圆角 6–8px；输入有明确标签，错误就地说明。
项目状态：整体状态、最近变化、更新时间分开，连接失效不覆盖为项目失败。
加载：静态骨架或短暂轻量过渡，保持版面稳定。
空状态：一句用途说明与一个合适入口，不使用大幅营销插画。
经验图：少量带中文名称节点；已有效与可参考关系分开，来源与适用性可查。
抽屉：经验详情和专业来源按需展开，不替代主要页面。

## 5. Layout Principles
导航：项目 / 问题与经验 / 我的工具；设置底置。
主要页面：项目总览、项目概览、问题与经验、我的工具。HUD 独立窗口。
设计基准 1280×820，兼顾 900×600；保持内容可滚动、操作可达，不宣称原生运行已验证。
侧栏约 184–208px，页边距 24–32px，间距 4/8/12/16/24/32px。
项目使用适合数据量的紧凑网格或列表，不机械套营销三等分特征卡。
无移动端要求。无 Hero、营销标语、封面大图或全屏无限画布。
HUD 约 360×440 为设计建议，支持更简短摘要；保留用量、会话、审批的访问入口。

## 6. Motion & Interaction
短暂交互 120–180ms，仅必要的 opacity/transform 过渡；尊重减少动态效果设置。
无常驻循环动效、数字滚动、背景漂浮、脉冲和无意义列表级联。
查看、筛选、复制无需确认。复制不等于执行。
详细技术内容按需展开，修改设置有明确入口，不在观察页放直接执行控制。
不为简单关系图引入大型图谱引擎。

## 7. Anti-Patterns
禁用媒体制作任务作为 WORK-LAB 的主要项目案例。
禁用内部阶段看板、任务节点编排、实时日志墙、运行时控制台。
禁用没有依据的完成百分比、成功率、已验证徽章和实时状态。
禁用“工具表示完成＝项目完成”“无更新＝暂停”“问题解决＝项目关闭”。
禁用默认跨项目自动应用、AAOS 入库和共享数据依赖。
禁用巨型统计卡、卡片套卡片、复杂图例、伪技术装饰和规则说明卡片。
专业能力和标准接口应保留在合适深度；轻量界面不意味着删除产品能力。
