# 一、Hermes 安装失败「全面排查清单」（Windows优先）

## 1. 先确认你装的是哪种 Hermes
很多人卡死是因为装错目标：

- ❗ Nous-Hermes（HuggingFace LLM模型）
- ❗ Hermes API / Agent 框架（Python项目）
- ❗ Ollama / LM Studio 里的 Hermes 模型
- ❗ Node / CLI 版本 Hermes 工具

👉 你必须先确认，否则后面全是错路。

---

## 2. 环境基础（90%失败点）

### ✔ Python版本
```bash
python --version
```

建议：
- Python 3.10 或 3.11（不要 3.12+）

---

### ✔ pip是否正常
```bash
pip --version
```

如果失败：
```bash
python -m ensurepip --upgrade
python -m pip install --upgrade pip
```

---

### ✔ 虚拟环境（必须）
```bash
python -m venv hermes_env
hermes_env\Scripts\activate
```

---

## 3. 依赖安装失败（最常见）

### 常见报错：
- Microsoft Visual C++ Build Tools missing
- torch 安装失败
- sentencepiece / tokenizers 编译失败

### 解决：

#### 安装基础编译工具
必须装：

- Visual Studio Build Tools
- C++ Desktop Development
- Windows SDK

---

#### PyTorch正确安装（关键）
如果你是 GPU：

```bash
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
```

如果 CPU：

```bash
pip install torch torchvision torchaudio
```

---

## 4. 网络 / 下载失败（国内高频）

表现：
- 卡在 `Downloading...`
- HF timeout
- pip 超时

解决：

```bash
pip install package_name -i https://pypi.tuna.tsinghua.edu.cn/simple
```

HuggingFace：

```bash
set HF_ENDPOINT=https://hf-mirror.com
```

---

## 5. GPU问题（你如果用本地模型）

检查：

```bash
nvidia-smi
```

如果没有：
- 驱动没装
- CUDA版本不匹配
- PyTorch装错版本

---

## 6. 权限 / Windows阻断

如果出现：
- Access Denied
- Scripts blocked

执行：

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```

---

## 7. 最容易忽略的坑

- 路径太长（Windows 经典问题）
- 中文路径（❌禁止）
- OneDrive同步目录（❌会锁文件）
- 杀毒软件拦截 pip / exe
- 代理冲突（VPN + pip冲突）

---

## 4. HuggingFace Hermes模型加载（示例）

```python
from transformers import AutoTokenizer, AutoModelForCausalLM

model_name = "NousResearch/Hermes-2-Pro"

tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    device_map="auto",
    torch_dtype="auto"
)

prompt = "Hello Hermes, explain AI agents"
inputs = tokenizer(prompt, return_tensors="pt")
outputs = model.generate(**inputs, max_new_tokens=200)

print(tokenizer.decode(outputs[0]))
```

→ 使用 HF 镜像：

### ❌ CUDA错误

### ❌ 安装卡死

所以我先不把它当成确定项目讲。一般来说，“Relay”类工具通常就是：

```text id="44m2qy"
客户端 → Relay → 模型 API
```

它更偏**API 中继 / 转发 / 代理**，不一定有 CCR 那种完整桌面 UI、路由规则、日志、Provider 管理、Codex Profile。

---

# 5. CCR 和 CCRelay 的区别

大概可以这样理解：

```text id="ne7geu"
CCR = 可视化路由器 + 本地网关 + 多 Agent 配置中心
CCRelay = 可能只是中继 / 转发 / API 代理
```

| 项目 | 作用 | 适合你吗 |
|---|---|---|
| CCR | 管模型、管路由、管 Codex/Claude Code/ZCode 配置 | 很适合 |
| CCRelay | 多半是 API 中继/转发 | 要看具体项目 |
| CC Switch | 快速切换配置 | 适合简单切换 |
| Hermes | 可视化 Agent / 模型调度 | 适合 DeepSeek 线 |
| Codex | 真正改仓库、跑代码 | 适合 GPT 工程线 |

---

# 6. 你的最佳用法

你现在可以这样搭：

```text id="5jr0mp"
A线：Hermes → DeepSeek
用途：资料整理、Obsidian 文档、需求拆解、低成本批量生成

B线：Codex → CCR → GPT / DeepSeek / Claude
用途：真实仓库修改、脚本开发、测试、排错、PR
```

这样比单纯：

```text id="293vig"
Codex → GPT
```

更灵活。

也比：

```text id="3ikq45"
Hermes → DeepSeek → Codex → GPT
```

更清晰。

---

# 7. 给你的结论

你可以把它们这样定位：

```text id="j4uavd"
Hermes：前台工作台，主要调 DeepSeek
CCR：模型路由总闸门，主要服务 Codex / Claude Code
Codex：工程执行员
GPT：高质量工程脑
DeepSeek：低成本整理脑
CCRelay：除非你给我具体项目，否则先当普通 API 中继看
```

我建议你优先研究 **CCR**，它比普通 CCRelay 更适合你现在的多模型、多电脑、Codex、DeepSeek、GPT 工作流。
