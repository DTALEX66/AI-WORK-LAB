## 1. 结论与定位锁定

本轮先修复“不真实的完成状态、配置事务、运行目录和生产门禁”，再做官方新版适配与增量增强。不能在这些缺陷之上继续叠加规则、技能或软件。

WORK-LAB 管理工作流软件的部署、用户层配置、规则、技能、插件/MCP、权限、版本、跨软件交接与执行证据。全局配置的含义是“一套管理规划和语义规则，按各软件官方接口投影”，不是让所有软件共用相同配置文件、相同运行目录或同一个 Agent 内核。

定位固定如下：

- Codex、Hermes、DSH 都是 WORK-LAB 受管工作流软件。DSH 不独立成第四项目，不由 WORK-LAB 重写其执行内核。
- WORK-LAB 保留已有 TaskPack、Work Unit、权限、任务委派合同、配置控制面、最小收据及恢复协调。Agent 内部规划、循环、线程、模型推理、会话存储由各软件负责。
- Control 可经批准调用配置事务；Observer 只读。不能把全部配置功能塞进只读看板，也不能因只读边界而删除原有合法控制职责。
- ComfyUI、ComfyUI-MCP、游戏和图像视频生产能力属于 DESIGN-LAB，本包不实现、不安装、不建立其业务流水线。
- Open Design “软件客户端”的通用安装/用户配置登记仍可属于 WORK-LAB；其设计能力与 DESIGN-LAB 项目自身配置不属于本包。
- ArcheAxis 的知识、证据和学习真值不在本包内。三个项目独立运行；只保留已约定的跨项目合同，不将另两项目作为本轮发布前置。
- 不另造聊天 UI、模型网关、Agent 框架、通用知识库或第二任务数据库。
- “个人研究、非商业使用”是使用目的；不据此替用户选择项目许可证，不据此忽略第三方授权条件。
- 此前已取消的“可复制个性化文案”不恢复为当前任务。本包讨论的是工程配置治理。

以上以本轮用户明确纠偏为准；旧文档若冲突，保留原文和裁决记录，不继续执行过期方向。

### 4.1 Codex 与 GPT-6：本轮必须补的治理

官方模型标识为 gpt-6-astra。官方迁移文档要求 Astra 工具调用使用 Responses；不支持 none/minimal 推理档及 temperature/top_p/logprobs 类参数。迁移已有配置时先保留有效推理强度，旧 none/minimal 才从 low 测试；不能把每个旧参数照抄进新模型。官方也特别要求检查 Skills/AGENTS 指令影响，因为新模型对这些指令更敏感。[官方迁移指导](https://developers.openai.com/api/docs/guides/latest-model)

WORK-LAB 实施要求：

1. 建立 client build × login method × provider × API protocol × model × feature 的能力矩阵。区分“原生 Codex 能用 Astra”和“Hermes/DSH 经过某 provider 能兼容 Astra”。
2. 原生 Codex 优先用官方模型入口。Hermes/DSH 若仅实现 Chat Completions 工具循环，不能只改模型名后宣称 Astra 完整支持；缺协议/工具参数证据时保持 UNSUPPORTED/BLOCKED_RUNTIME。
3. registry 应记录 requested_model 与 resolved_model，未知不猜测；错误码和回退必须可见，禁止把不支持参数悄悄删除后仍宣称行为不变。
4. Astra 承担复杂诊断、迁移规划和长链任务评估；简单重复任务可把 Terra/Luna 作为经用户批准的对照候选。不得偷偷降档，也不强制每件事都旗舰+最高强度。
5. 任务级资源策略区分用户指定强度、批准的实验开销、软告警、硬限制。不私加全局日/月上限；旧“无限资源”或“一律最高强度”与新按任务策略的冲突需显式裁决。
6. 把代理委派设计成原生可执行策略：有独立边界、输入摘要、负责文件、结果合同和可取消性时才委派；子任务不得提升权限或无限递归。执行者不应再安装一套功能重复的总管框架。
7. 在“官方默认+必要安全边界”“当前旧配置”“精简规则+按需技能”三组上比较效果，保持任务/模型可比，不能只比较 Token 数或引用营销 benchmark。
8. Codex 实验性上下文管理只在账户/客户端支持且用户选择后试用，不默认全局打开，也不把同一任务的消息检索当成所有历史对话已归档。[官方模型与上下文能力](https://learn.chatgpt.com/docs/models)

原则：统一语义，不强制统一文件格式与软件原生优先级。

### 6.2 E 盘与防外溢

E 盘未经用户明确授权不得访问，包括读取、列目录、探测文件存在、索引、截图/OCR 后转述或通过链接间接访问。测试使用合成路径/模拟文件系统；不以“验证拒绝规则”为理由触碰真实 E 盘。

权限控制须考虑盘符大小写、相对路径、junction/symlink、UNC/设备路径、WSL 映射及子进程。只靠字符串 startswith 或 Hook 黑名单不够；无有效隔离时清楚报告能力限制，不写“已保证防外溢”。

出站控制按目标域名、操作、数据类型与 task scope 授权。风险面包括 MCP 参数、网页搜索 query、终端 stderr、Hook 输出与临时溢出文件、CI artifact、Git diff、浏览器、备份和遥测。外部请求只发送最小必要内容，不自动上传代码/记录；副作用请求经批准后仍需收据。

Codex 官方明确 hosted tools 不走同一 local Hook 路径，write_stdin 不重复触发 PreToolUse；某些无效 Hook 输出会记录错误后继续。因此使用 OS/沙箱/工具授权/网络策略作为真实限制，Hook 作为可测试的辅助控制。异步 post-hook 不可回滚已发生的副作用。[官方 Hook 覆盖与限制](https://learn.chatgpt.com/docs/hooks)
