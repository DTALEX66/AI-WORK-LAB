## 1. `mikechambers/adb-mcp`
### 我最建议你先研究这个架构

urlmikechambers/adb-mcp GitHubhttps://github.com/mikechambers/adb-mcp

它原本主要是：

**AI → MCP → Proxy → Adobe UXP Plugin → Adobe**

官方 README 已包含 Photoshop、Premiere，并且现在仓库中还存在 Illustrator、After Effects、InDesign 对应 MCP/桥接实现。Photoshop / Premiere 使用 UXP，而 AE / Illustrator 使用 CEP 路线。它也明确测试过 Claude Desktop、Windows/macOS，以及 OpenAI Agent SDK。citeturn981977view1

架构大概是：

```text
Codex / Claude / Hermes
          ↓
         MCP
          ↓
Adobe Control Server
          ↓
WebSocket Proxy
          ↓
 ┌────────┼─────────┐
 ↓        ↓         ↓
PS UXP   PR UXP    ID UXP
 ↓
Photoshop

AE / Illustrator
      ↓
     CEP
      ↓
 ExtendScript
```

这个项目真正有价值的地方不是单纯“能修图”，而是：

**它已经把“LLM → Adobe”的通信层给你搭出来了。**

很适合作为统一 Adobe Adapter 的参考基线。

# 2. `jinkeda/Illustrator_MCP`

urljinkeda/Illustrator_MCP GitHubhttps://github.com/jinkeda/Illustrator_MCP

这个我反而非常看好。

因为它不是简单搞：

> AI 写 JSX → Illustrator 执行

而是已经开始解决 AI 操作设计软件最麻烦的问题：

**AI 怎么知道自己画对没有？**

它的架构是：

```text
AI
 ↓
MCP
 ↓
Python Server
 ↓
WebSocket
 ↓
Illustrator CEP
 ↓
ExtendScript
```

Windows 有明确安装支持。citeturn988818view1

更重要的是它做了：

**VLM Visual Grounding。**

例如 AI 创建设计以后，会生成带编号 Bounding Box 的预览：

```text
[1] Logo
[2] Headline
[3] Button
[4] Background
```

然后：

```text
视觉对象 [2]
        ↓
对应 Illustrator DOM 对象
        ↓
@mcp:id
        ↓
AI 精确修改
```

不是：

> “大概点一下左边那个文字。”

而是：

> “修改 `@mcp:a1b2c3` 对象，向左移动 12 pt。”

它甚至做了：

- annotated preview
- DOM map
- before/after diff
- overlap 检测
- alignment 验证
- occlusion guard
- 定期视觉 QA
- 空间关系验证

citeturn988818view2turn988818view3

### 这已经非常接近我认为正确的 AI 设计 Agent 架构：

```text
理解设计
    ↓
执行
    ↓
视觉查看
    ↓
DOM 验证
    ↓
设计 QA
    ↓
修改
    ↓
再次验证
```

而不是传统：

```text
Prompt
 ↓
生成
 ↓
结束
```

# 3. Photoshop：`ajfonthemove/photoshop-mcp`

urlajfonthemove/photoshop-mcp GitHubhttps://github.com/ajfonthemove/photoshop-mcp

这个很有意思。

它选择了另一条路线：

> **不装 UXP Plugin。**

而是在 Windows 上直接通过：

```text
MCP
 ↓
COM Automation
 ↓
ExtendScript
 ↓
Photoshop
```

macOS 则是 AppleScript。

目前提供约 **42 个 Photoshop 工具**，覆盖：

- 图层
- 选择
- 调整
- 滤镜
- 文字
- Shape
- Transform
- Export

更关键的是：

它也有：

**preview / screenshot**

所以 AI 不只是读取 Photoshop 对象结构，还能看到当前 Canvas。citeturn571392search7

对于 Windows 用户，这种方案相当值得测试。

# 4. Photoshop 极限工具量：`00bx-photoshop-mcp`

url00bx/00bx-photoshop-mcp GitHubhttps://github.com/00bx/00bx-photoshop-mcp

这个走的是：

```text
OpenCode
 ↕
MCP
 ↕
Python
 ↕
Node Proxy
 ↕
UXP
 ↕
Photoshop
```

目前号称：

**323 个 Photoshop Tools + 7 个 AI Skills。**

包括：

- Layer
- Selection
- Mask
- Text
- Blend mode
- Filter
- Effect
- BatchPlay
- Photo Effect
- Text Effect
- Export

它本身也是从 `adb-mcp` 扩展出来的。citeturn280073search14

它的优势是：

**覆盖广。**

但我不会直接拿这 323 个 Tool 全塞给 Agent。

原因很简单：

```text
323 MCP tools
↓
模型工具选择复杂度
↓
Token / Tool schema 成本
↓
误调用概率
```

更好的方法反而是：

```text
Photoshop Skill
    ↓
Tool Router
    ↓
323 Low-level Tools
```

让 Agent 看到的可能只有：

```text
photoshop.inspect
photoshop.edit
photoshop.compose
photoshop.retouch
photoshop.export
```

内部再路由。

```text

      ↓
     MCP
      ↓
AE MCP
      ↓

      ↓
```

**30 个设计合理的 Tool > 300 个碎片 Tool。**

```text

ae.modify_layer()

ae.animate_property()

ae.apply_effect()

ae.preview()

ae.render()
```

而不是暴露数百个最底层函数。

# Adobe 官方基础也必须保留

还有一个经常被忽略的部分：

Adobe 自己已经正式把 **UXP** 定位为新一代扩展平台。

Photoshop 官方明确支持：

- UXP Scripts
- UXP Plugins
- Hybrid Plugins
- Photoshop DOM
- BatchPlay

并且 ExtendScript / CEP 已经属于 legacy 路线。citeturn499110search2turn499110search6

官方还有完整开源 Sample：

urlAdobe Photoshop UXP Plugin Sampleshttps://github.com/AdobeDocs/uxp-photoshop-plugin-samples

citeturn499110search5

Premiere 现在也已经有正式 UXP API，包括：

**Sequences、Tracks、Clips、Markers、Project Items 等 DOM API。** citeturn499110search0

所以长期来看应该：

```text
官方 API
优先
↓
UXP
↓
ExtendScript
↓
CEP
↓
COM
↓
最后才是 GUI 鼠标视觉控制
```

而不是反过来。

# 我更建议的完整架构

如果是给你的 **DESIGN-LAB** 使用，我会直接把这些项目拆开吸收，而不是选一个。

```text
DESIGN-LAB
│
├── Creative Agent
│
├── Design Planner
│
├── Visual QA Agent
│
└── Adobe Tool Router
          │
          ▼
    Adobe Control Gateway
          │
 ┌────────┼────────┬─────────┬──────────┐
 ▼        ▼        ▼         ▼          ▼
PS       AI       AE        PR         ID
│        │        │         │          │
UXP      CEP      CEP       CEP/UXP    UXP
│        │        │         │
MCP      MCP      MCP       MCP
```

再把外部这些项目吸收成 Adapter：

```text
adapters/
└── adobe/
    ├── core/
    │   ├── mcp-gateway
    │   ├── tool-router
    │   ├── capability-registry
    │   ├── checkpoint
    │   └── visual-verifier
    │
    ├── photoshop/
    │   ├── adb-mcp
    │   ├── photoshop-mcp
    │   └── uxp
    │
    ├── illustrator/
    │   └── illustrator-mcp
    │
    ├── after-effects/
    │   ├── ae-mcp
    │   └── ae-agent
    │
    ├── premiere/
    │   └── premiere-mcp
    │
    └── indesign/
        └── indesign-adapter
```

这样最终就不是“让 AI 帮你按按钮”，而是：

> **AI 理解设计任务 → 选择 Adobe 软件 → 打开文件 → 读取图层/对象 → 执行设计 → 截图 → VLM 视觉审查 → DOM 数值审查 → 自动修改 → 人工确认 → 导出。**

这才是真正适合职业设计工作流的 **Adobe Agent Control Plane**。

如果只让我现在挑 **4 个优先吸收**，顺序我会定成：

**`jinkeda/Illustrator_MCP` → `mikechambers/adb-mcp` → `hetpatel-11/Adobe_Premiere_Pro_MCP` → `tiansuo-114/AE-agent`。**

尤其是 **Illustrator_MCP 的“VLM + DOM 双重校验”设计，值得直接变成所有 Adobe Adapter 的公共标准**。memcite
