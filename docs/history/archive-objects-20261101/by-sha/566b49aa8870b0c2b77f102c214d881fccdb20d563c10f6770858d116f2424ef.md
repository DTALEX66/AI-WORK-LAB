## P0-01：Portable Verifier 存在假验证

机器清单要求运行时支持：

```yaml

  - quick_commands
  - model_picker.custom_lanes
  - hermes_config_check
```

fileciteturn8file0L19-L28

但 `verify_portable_install.py` 对 `hermes_config_check` 的验证方式是直接写死：

```python
"hermes_config_check": True
```

脚本自己也注明，真实 `hermes config check` 应在独立集成门禁执行。fileciteturn16file0L79-L93

### 影响

CI 可以显示 portable install 通过，但并未证明：

- Hermes 能解析该配置；
- `config_version: 33` 与已安装 Hermes 匹配；
- `quick_commands` 和 custom lanes 真被当前运行时识别；
- Context7 配置能被 Hermes 加载。

### 修复

二选一：

1. 从当前 structural verifier 的 required features 中移除 `hermes_config_check`，改名为 `hermes_config_check_declared`；
2. 新建真正的 `integration-hermes.yml`，安装或绑定受支持 Hermes 版本，在隔离 Home 中执行：

```bash
hermes config check
hermes hooks doctor
hermes mcp list
```

只有第二类门禁可以输出 `RUNTIME_COMPATIBILITY_PASS`。

## P0-02：Workflow Doctor 可以失败后仍返回 OK

Doctor 会调用：

- `hermes --version`
- `hermes config check`
- `hermes auth list`
- `hermes mcp list`

但多数命令的退出码只被打印为 `WARN`，没有加入最终失败集合。fileciteturn28file0L258-L290

Context7 检查和 Codex 版本检查也存在相同问题：命令可能失败，但结构模式最终仍输出：

```text

```

fileciteturn29file0L3-L25 fileciteturn29file0L57-L68

### 影响

以下场景可能被误报为整体正常：

- Hermes 配置损坏；
- MCP 配置无法解析；
- Context7 无法启动；
- Codex 文件存在但不能执行；
- Auth 命令异常。

### 修复

检查必须划为三类：

```text
REQUIRED
- hermes --version
- hermes config check
- hermes auth list
- hermes mcp list
- 至少一个可执行 Codex 候选

OPTIONAL
- CC Switch 端口
- Codex Router 端口
- Context7 网络请求
- DeepSeek/ChatGPT HTTP 可达性

LIVE
- GPT marker
- DeepSeek marker
- Kimi marker
- Codex exec marker
```

任何 REQUIRED 失败，Doctor 必须退出非零，不得输出最终 OK。

同步器具备优点：

- 只清除明确登记的退役资产。fileciteturn17file0L3-L8 fileciteturn17file0L128-L188

- 中途失败没有自动恢复；
- `copytree(..., dirs_exist_ok=True)` 可能留下新旧混合文件；
- 只保留最近两份同步备份；
- 没有正式 `restore` 命令；
- 应用后没有强制 `hermes config check`。

### 修复

安装流程改成：

```text
preflight
  ↓
dry-run plan
  ↓
create complete snapshot
  ↓
deploy into staging home
  ↓
structural verification
  ↓
atomic swap / file replace
  ↓
hermes config check
  ↓
hooks doctor
  ↓
live provenance check
  ↓
success marker
```

任何步骤失败：

```text

→ verify restored hash
→ retain failure evidence
→ exit non-zero
```


## P0-06：高低风险完全由调用者自报

- `config/**`
- `scripts/security/**`
- `scripts/workflow/sync_*`
- `bin/hermes-project-*`
- 删除、迁移、认证或 Provider 逻辑

从而绕过独立复审。

### 修复

新增自动风险分类器：

```yaml
forced_high_risk:

    - .github/**
    - config/**
    - setup.*
    - scripts/security/**
    - scripts/workflow/sync_*

    - delete
    - move
    - credential
    - provider_change
    - publish
    - external_path_write
    - workflow_change
```

规则：

```text

        =
最终 risk=high
```

并规定所有 `--publish` 都必须携带 OpenHuman 或用户审批 manifest。
