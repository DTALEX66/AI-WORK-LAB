这个应该直接进下一轮 **P0 修复**。

PR #175 的最新 Canonical Verify：

**九个核心 Gate 全部 SUCCESS：**

Python、MiniGame、Generated-artifact、License/Secret、Open Design、Authority、Workbench strict TS、Workbench browser E2E、DeepSeek Authority。

失败的是额外：

`CI artifact proof (H001)`

而且 artifact 实际已经上传成功。

真正报错：

```text
RUN-SHA-MISMATCH
run.head_sha = 06e60723...
expected_sha = e1fb76ba...
```

根因已经定位：

在 `pull_request` 事件中：

```text
github.sha
= PR synthetic merge ref SHA

GitHub Actions API run.head_sha
= PR source head SHA
```

当前 verifier 把这两个身份错误地当成必须相等。

所以 H001 不是“Artifact 上传失败”，也不是之前的 415。

**这是 PR 双 SHA 身份合同设计错误。**

修复不要写成：

```text
if a == b or a == c: pass
```

而要正式建立：

```text
run_head_sha
subject_tree_sha
merge_sha
event_type
```

Push：

```text
run_head_sha == subject_sha
```

PR：

```text
run_head_sha == pull_request.head.sha
subject_tree_sha == github.sha (merge ref)
```

Artifact 则继续绑定实际测试过的 **subject tree**。

这样才不会把验证放松成“任一个 SHA 对上都算”。

另外 H001 自己已经声明 `gate=ADVISORY`，那最好也不要让整个 Canonical Verify 在 GitHub UI 上呈现整体 FAILURE。

应该：

**Required gates 失败 → workflow red。**

**Advisory artifact proof 失败 → visible warning / summary / separate advisory status。**

Release Gate 仍然保持 fail-closed。
