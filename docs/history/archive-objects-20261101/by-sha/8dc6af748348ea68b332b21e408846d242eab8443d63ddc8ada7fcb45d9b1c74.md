# 三、ChatCut：值得接，但位置必须重新定义

这是这批候选里，对 DESIGN-LAB **产品能力提升最直接**的一个。

报告核验的能力包括素材导入、时间线修改、字幕、动效、导出以及编辑器状态检查，并且能够通过 Codex、Claude Code 等宿主操作 ChatCut 项目。fileciteturn0file0L388-L407

它刚好符合 DESIGN-LAB 的正确模式：

**DESIGN-LAB**
→ 负责脚本/Storyboard/品牌规范/字幕标准/视觉规范/交付标准

**Codex / Agent**
→ 理解任务并调用 Adapter

**ChatCut**
→ 真正执行视频编辑

**DESIGN-LAB**
→ Readback + Quality + Preflight + Handoff

所以完全不需要 DESIGN-LAB 自己开发一个视频剪辑器。

但有一个非常重要的审计修正：

### ChatCut 不能直接把现有 Premiere 任务标记完成

现在 DESIGN-LAB 的 R5 任务里已经有：

`DL-R5-019 — Premiere 可编辑视频`

目标是：

`可编辑项目 + 音轨 + 字幕 + 保存重开 + 媒体重连`

如果接入 ChatCut，它应该首先进入：

**DL-R5-021 可选 Host / Agent 收敛**

做一个独立的：

`ChatCut Qualification`

而不是：

`ChatCut E3 PASS → Premiere E3 PASS`

二者必须分开。

否则以后 PROJECT_STATUS 会出现典型的“用 A 软件证据替 B 软件完成度”的问题。

ChatCut 真正验收应该按照报告建议：

`素材导入 → 时间线编辑 → 字幕/动效 → Readback → 关闭 → 重开 → 再读 → 导出 → 文件检查`

而不能只看 Agent 返回“完成”。fileciteturn0file0L409-L417

**Prompt ≠ Method**

# 十、我建议 DESIGN-LAB 按这个顺序执行

1. **先完成当前核心 P1**：`DesignSystem → DesignIR → Photoshop/Illustrator → editable → readback → patch/reopen → Human Jury → Preflight/Handoff`。这才是 DESIGN-LAB 从“设计能力框架”变成“真实生产系统”的关键一步。

3. **建立 External Design Capability Intake**，把 Prompts.chat、ChatCut、Jev、后续 Figma/Blender/Adobe 插件等统一经过 `SOURCE → LICENSE → CONTRACT → SANDBOX → E2 → E3 → ABSORBED/REFERENCE/REJECTED`，而不是见一个项目建一个新模块。

4. **ChatCut 做第一批新增 Host 资格验证**，但定位为“视频 Host Adapter / Golden Workflow”，不替代 Premiere，不修改现有视频任务的证据归属。

5. **第二批才做 Jev + Method intake + 经验沉淀**；Beacon 留给 WORK-LAB 做跨软件证据聚合，GEP 只借 Schema 思想，SoL-Pi 只借效率方法，OpenMausBot / Oh-My-Hermes / EigenFlux 暂时不要进入 DESIGN-LAB 核心。
