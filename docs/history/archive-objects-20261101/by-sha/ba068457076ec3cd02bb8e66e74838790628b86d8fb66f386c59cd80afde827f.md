## 2. 最终产品定位

### 2.1 一句话定位

ArcheAxis Knowledge 是一个本地优先、原件永久保全、证据驱动、开放互操作、数据主权可控，面向人类与 AI 双主体进行双向学习和可信知识治理的系统级平台。

### 2.2 核心价值

- 用户原始资料默认留在本地，未经授权不扫描私人目录、不上传云端；
- 原件永久保全，任何 OCR、ASR、摘要、索引、向量和模型产物都属于可重建派生物；
- 所有 Claim、知识、学习材料和 AI 资产均可追溯到来源、页码、坐标、时间戳或 DOM 节点；
- 内容冲突不自动覆盖，不可查证内容不强行验证，低置信结果进入人工复核；
- 同一 EvidenceBundle 同时支持人类学习和 AI 复用，但两条链路的状态、指标和审批互相独立；
- 全部资产可撤销、替换、失效、回滚和开放格式导出；
- 插件、模型和外部软件可替换，可信知识语义与用户资产不能依赖某个供应商。

### 2.3 人机双向学习

```text
可信原件与证据
├─→ 人类学习：理解、概念拆解、练习、间隔复习、迁移、Teach Back
└─→ AI 学习：记忆、规则、技能、标准、上下文、评测集

人类修正/质疑 ─→ 证据审阅队列
AI 发现冲突/缺失 ─→ 人工复核队列
```

AI 只是学习主体之一。产品首页不应被聊天框、Agent 或模型控制台占据。

### 2.4 明确不是

ArcheAxis 不是：

- 通用 Agent OS 或 Agent Runtime；
- WORK-LAB 的知识插件或数据库；
- DESIGN-LAB 的内部知识库；
- 模型管理、GPU 调度或通用自动化平台；
- 聊天工具、纯 PDF 阅读器、文件管理器、RAG 壳；
- Obsidian 克隆；
- 以某个 OCR、LLM、向量库或 3D 引擎为核心的封装产品。

- Command、Receipt、Event 和数据契约；

### 5.2 可替换能力

- 搜索、向量、图谱等可重建 Projection；


- 获得核心数据库句柄或直接写核心表；

- 绕过 Evidence、人工复核、权限与审计；
- 将模型输出、网页内容或识别置信度自动升级为可信知识；
- 因禁用或卸载而破坏 canonical data；
- 首次调用时静默下载模型、引擎或大体积依赖。

## 7. 多格式摄取与转化主链

### 7.1 统一主链

```text
来源 / 文件 / URL / 授权导出 / 用户辅助采集
→ PolicyGate
→ SourceRouter + 格式指纹
→ RawAsset / WebSnapshot / CaptureBundle（原件保全）
→ RoutePlan
→ 本地低成本引擎
→ ConversionResult + Anchors + LossReport + Provenance
→ 必要时多引擎仲裁或 LLM/VLM 辅助
→ Candidate Claim / Evidence
→ 权威来源交叉核验 + 人工复核
→ EvidenceBundle / KnowledgeVersion
├─→ Human Learning Asset
└─→ Governed AI Asset
→ 导出 / 备份 / 重启回读
```

### 7.2 格式与首选引擎方向

| 类型 | 首选低成本路径 | 升级条件 |
|---|---|---|
| 文字 PDF | markitdown / pdfplumber | 结构、覆盖率、乱码或锚点风险高 |
| Office | markitdown + mammoth/pptx/openpyxl/pandas | 图表、阅读顺序或对象丢失严重 |
| HTML/网页 | trafilatura / 结构化解析 / 受控浏览器快照 | 动态内容、登录态、脚本渲染或布局结构缺失 |
| 图片/扫描 PDF | Tesseract / RapidOCR / PaddleOCR/EasyOCR 等可替换 OCR | 多引擎分歧、公式/表格/版面高风险 |
| 音频 | VAD + faster-whisper / FunASR/SenseVoice | 噪声、多人、术语或时间轴风险高 |
| 视频 | 平台字幕 → 音轨 ASR → 关键帧/OCR | 字幕缺失、画面信息重要、结构复杂 |
| Markdown/Canvas/JSON/CSV | 原生结构解析 | schema 不兼容或引用丢失 |

引擎清单是适配方向，不是强制同时安装。无引擎时必须诚实报告 `degraded/model_missing/engine_missing`，不得伪造成功。

### 7.3 识别层与事实层必须解耦

**识别转译层：** 文本、版面和时间轴转得准不准。

- 有人工金标准时：CER、WER、表格/布局指标、锚点准确率；
- 无金标准时：只能给风险分，组合覆盖率、结构保留、乱码/重复、语言一致性、阅读顺序、锚点完整、多引擎一致度；
- 无金标准时禁止把自报置信度称为“准确率”。

**内容事实层：** 转译出的 Claim 是否真实。

- 对可公开查证事实使用官方文档、原始来源、学术/图书馆资料和多个独立来源；
- 保存支持、反驳、未知、时效和适用范围；
- 争议不自动覆盖原文；
- 私人记录、主观观点、非公开信息、纯噪声和不可查证内容跳过验证并记录原因。

### 7.4 多引擎融合

- 块级或句级对齐，不做整篇静默覆盖；
- 保存各引擎候选、版本、参数、差异和选择原因；
- 优先使用结构完整、锚点稳定且风险最低的结果；
- 高分歧区域进入人工复核；
- LLM 只用于困难区域辅助，不作为默认全文件重复识别器。

## 8. 网页、媒体平台与小程序采集边界

涉及微信小程序、抖音、小红书、B 站、YouTube、X 等平台时，目标是用户授权范围内的研究型采集和 UI/内容审计，不是无边界爬虫。

允许的输入：

- 用户主动导出的数据和文件；
- 官方 API 或平台提供的下载/字幕；
- 用户正常登录后，明确操作范围内的可见截图、录屏、字幕、DOM/无障碍树和交互路径；
- 用户保存的网页快照、HAR 中不含敏感凭据的结构信息、公开链接和页面元数据。

禁止：

- 索要或读取密码、Cookie、Session Token；
- 绕过验证码、登录墙、付费墙、DRM、风控或访问控制；
- 批量抓取未授权私人内容；
- 把页面/平台内容直接升级为 Approved Knowledge；
- 把单一平台的排名、点赞或模型摘要当成事实权威性。

所有此类内容进入 `CaptureBundle/WebSnapshot → candidate`，保留时间、范围、采集方式、损失报告、证据锚点和用户授权记录。

已有专项任务包名称：`AXW_WEB_CAPTURE_INGESTION_HARDENING_TaskPack_v3_2026-08-15.md`。

## 9. 差异化核心技术与算法方向

这些是系统护城河和研发方向；在基准、消融和真实数据证明前，不得宣传为已完成“突破”。

### 9.1 Anchored Provenance Graph

将 Claim、KnowledgeVersion、LearningAsset 和 AIAsset 绑定到不可变原件版本及页码、bbox、时间戳、DOM/Canvas 节点。指标：锚点存活率、跨版本重定位、引用回读和派生链完整率。

### 9.2 Loss-aware Conversion Router

基于格式指纹和损失风险选择成本最低的本地引擎，仅在必要时升级多引擎或模型。指标：固定人工接受率/CER/WER 下的成本、时延、能耗和 LLM 调用率。

### 9.3 Independent-source Evidence Engine

识别来源家族、转载关系、权威等级、时效、原始/二手来源和独立性。指标：Claim 识别、支持/反驳分类、独立性误判和过期事实召回。

### 9.4 Reversible Knowledge State Machine

知识以版本链存在，带来源、范围、时间、争议和状态，支持失效传播、替换和解释性回滚。

### 9.5 Dual Learning Compiler

同一 EvidenceBundle 分别编译为 HumanLearningAsset 与 GovernedAIAsset；人类侧评估保持、迁移和误区修正，AI 侧评估引用、约束和证据覆盖。

### 9.6 Learning Representation Compiler

定义引擎无关的 `LearningRepresentation` 和 `SpatialMemoryPackage`，再由插件渲染为静态图、动态图、动画、模拟、2D/2.5D/3D 记忆宫殿和 VR/AR。

### 9.7 宣称技术突破的门槛

- 可复现的多格式金标准；
- 单引擎、无门控、普通 RAG/笔记流 baseline；
- 消融实验；
- 识别、事实、引用、成本、人类学习和 AI 复用的分层指标；
- 失败样本、适用边界和不确定性报告。

## 10. UI/UX 与桌面产品方向

### 10.1 技术方向

- 保留 Tauri 2 Windows 桌面壳和本地 FastAPI；
- 前端渐进迁移为 React + TypeScript + Vite；
- 从 OpenAPI 生成类型安全客户端；
- Tauri 内置 Recovery Shell，Python 后端停止或迁移失败时前端仍能显示、重连和查看日志；
- `OSUI/` 仅作设计参考，不再形成第二套运行 UI 真相；
- UI 插件只通过受控 Contribution Manifest 添加二级视图，不可覆盖固定一级导航。

### 10.2 固定信息架构

```text
顶部：全局搜索 / Command Palette / 当前工作区 / 任务与同步状态

一级导航：
  Workspace
  Library（资料库）
  Evidence（证据）
  Learning（学习）
  AI Assets
  Settings

左二：当前空间集合、筛选与上下文
中央：Reader / Editor / Canvas / Learning Surface / Asset Editor
右侧：来源、证据、冲突、引用、属性和历史 Inspector
底部：转换、索引、核验、导入导出 Activity Dock
```

终端、浏览器、Agent、模型控制台不进入固定一级导航，仅能作为可选二级工具视图。

### 10.3 视觉与交互原则

- 好看、功能兼容、高效率三者同时满足；
- 专业、安静、证据感强，信息密度高但不拥挤；
- 主工作面使用实色或低透明表面，玻璃仅用于浮层和短暂状态；
- 中性底色 + 单一品牌主色 + 支持/冲突/未知/失效语义色；
- 150–220ms 状态动效，尊重 reduced motion；
- 知识和 AI 资产页面一键打开原件锚点、证据束、冲突和版本；
- 最低 1280×720、高 DPI、键盘和读屏可用；长列表虚拟化，后台任务不阻塞主线程。

### 10.4 必须消除的 UI 漂移

- 第三方品牌只在 Adapter 设置和兼容说明出现；
- 真实 read-only 模式不能展示可执行保存；
- AI Assets 不能藏进“系统”页；
- 统一 queued/running/blocked/needs-review/failed/succeeded/cancelled；
- 不混用 mock 与真实 API；
- “已完成/已启用”必须来自 capability/readiness API，不能硬编码。

## 11. 运行模式和发布结构

### 11.1 Backend Supervisor

```text
Tauri 前端常驻
  ├─ Bundled Stable Backend       标准安装版
  ├─ Bundled Green Backend        绿色免安装版
  ├─ Bundled Portable Backend     随身便携版
  └─ External Dev Backend         外接源码、热重载、隔离测试库
```

正式安装目录中的后端不得被随意改写。开发时前端保持打开，通过 External Dev Profile 启停、重启和热重载源码后端；默认使用隔离测试工作区，不直连生产数据。

### 11.2 公开交付形态

1. `Setup`：标准安装版，稳定日常使用；
2. `Green`：解压即用，程序免安装，数据默认不随程序移动；
3. `Portable`：程序、数据、能力和配置均在便携根，可整体迁移；
4. `Developer Kit`：内部测试产物，不作为普通用户正式版。

可选完整离线便携包可以包含固定 WebView2，但不应成为默认包。

### 11.3 关键安全规则

- 后端仅绑定 loopback，随机端口 + launch token；
- CSP、origin、navigation、SSE、下载和 PDF 路由 fail-closed；
- external-dev 必须显式启用并显示明显 DEV 标识；
- 正式、绿色、便携和开发使用不同 runtime identity；
- API key 进入 Windows Credential Manager 或等价安全存储；
- 日志脱敏，不记录正文、Token、密钥和完整私人路径；
- 插件崩溃不得带崩 Tauri Shell 或可信内核；
- 卸载不删除用户四库；
- 数据迁移必须备份、完整性检查、回滚和重启回读。

## 13. 当前最短真实闭环

当前目标不是“代码里有入口”，而是至少一个真实样本能走完整链：

```text
导入原件
→ 原件哈希和永久保全
→ 格式检测与本地转换
→ OCR/ASR/结构/锚点/LossReport
→ Candidate Claim/Evidence
→ 人工复核或权威来源核验
→ EvidenceBundle
→ 生产写入器写入 Human Learning 与 AI Asset
→ 前端真实显示
→ 导出
→ 应用重启后回读一致
```

### 13.1 推荐阶段顺序

```text
R0 当前云端事实、单一命名和必要门禁
→ R1 Workspace Manifest、四库、路径选择和迁移
→ R2 常规全格式摄取、OCR、ASR、LossReport、失败恢复
→ R3 Evidence 状态机、人工复核、Human/AI 生产写入器
→ R4 React 正式 App Shell 和六大空间
→ R5 Tauri Recovery Shell、Supervisor、External Dev Backend
→ R6 Setup / Green / Portable 真实发布闭环
→ R7 Web / 媒体平台受控采集增强
```

### 13.2 基础闭环完成定义

只有同时满足以下条件，才可称为基础闭环完成：

1. 当前 main CI 与 Nightly 真实绿色，无已知生命周期竞态；
2. 命名、版本、Capability 状态只有一个权威源；
3. 常规格式完成原件、转换、锚点、阅读/检索和失败恢复；
4. 识别质量与内容事实验证严格分层；
5. 冲突不自动覆盖，低置信进入人工复核；
6. Human Learning 与 AI Asset 共享证据但独立生效；
7. 断网、无云模型、无可选插件时基础核心可运行；
8. 至少一种 OCR/ASR/Search/Model 能力完成真实可替换验证；
9. 六大空间、Activity Dock 和 Evidence Inspector 使用真实 API；
10. Windows 安装、启动、升级、卸载、数据保留和回读通过；
11. 开放格式导出可用，禁用插件不破坏 canonical data；
12. 未来 LER/动画/空间/3D/VR/AR 契约仍保留。
