# 扩展方式、科研开发与难度分期｜R5

## 不是一种插件承担全部能力
| 方式 | 适用内容 | 必须另外核验 |
|---|---|---|
| 现有内置模块/SDK | 阅读、编辑、解析、算法、可视化 | 版本、许可、对象/状态兼容、是否已有消费者 |
| 前端活动渲染组件 | 图解、视频、画布、参数面、2D/3D | 受限资源、草稿/返回、降级；不直写业务库 |
| 受控worker/引擎 | OCR/ASR、计算、动画产物、仿真 | 输入类型、依赖、隔离、预算、取消、结果校验 |
| 技能/规则/知识包 | 方法、指导、提示、可复用知识 | 来源、内容版本、范围、评测与采用；文本不自带执行授权 |
| 受控插件包 | 已知可扩展组件与依赖组合 | 既有包合同、身份、权限、启停/更新/回退与旧对象访问 |
| MCP | 对方实际暴露的工具、资源、提示 | 协议/SDK版本、方向、schema、鉴权、权限、真实工具语义 |
| API/SDK | 科研平台、检索、计算或生成服务 | 实际端点/版本、费用、数据去向、限流、合法内容范围 |
| 受控CLI/外部播放器 | 本地专用计算、3D播放器等 | 明确程序身份、参数与路径范围、进程状态和产物收回 |
| 文件/交换包 | 笔记、题录、课件、数据与代码产物 | 方向、版本、样本、附件/关系损失、往返与增量分别验 |

插件是交付与加载方式，技能主要承载知识/行为指导，MCP是通信接入方式，API/CLI是外部调用方式。它们可以组合，不是可互换的万能标准，也不保证任意厂商插件可直接运行。
可识别接口不等于任务已获准，工具可达不等于执行成功，外部输出不自动成为可信知识。

## 四类难度
D1复用型：基于已有能力呈现或接线。并非零成本，也不表示已实现。
D2业务扩展型：需要对象、状态、持久化、权限或单一适配。
D3专项实现型：特定引擎、复杂互通、设备、迁移或跨层集成。
D4研究验证型：工具能力、科学效果、平台限制或自动循环仍需研究。
同一能力可以有不同层级：保存实验计划可先做，真实仿真引擎后期，自动提出假设并实验验证更远期。
附件逐行等级是设计估计，待本地结合现有代码调整。不能由难度机械推算工期或把原required延期。

## 三阶段与当前底座
P0核验现有范围；P1最小对象/契约/状态承接；P2后期具体工具/引擎；P3远期研究与重型运行。
预留可以是说明、稳定输入输出引用、结构化未接入状态和返回路径；不要求现在写假后端、注册一个永远成功的worker或空实现凑覆盖数。
若已有功能真实运行，保留其现状与证据，不因本包把它倒退标待开发。

## 科研与开发能力如何并入
研究与比较：问题与范围→材料→假设与反证→方法→实验计划→数据/代码与计算→结果→复现→结论/未决。允许独立保存计划和人工判断。
- 文献题录/公开检索：优先复用现有研究适配，按实际required验收。
- 数据处理/统计/代码分析：以受控计算或工具adapter扩展，保存数据哈希、环境、算法、参数和产物引用。
- 仿真实验/数值计算：复用学习仿真结果与Job边界，研究目标/评价另行表达。
- 论文分析/研究辅助Agent：逐工具确认API/MCP/CLI等真实接口，当前仅候选，不凭名称宣称兼容。
- 自动假设、复杂实验循环、集群或实体设备：D4，明确预算、授权、可复现、停止与人工判断，后期独立准入。
- 开发辅助：代码/研发资料可入库和分析；跨仓库写代码、部署与复杂编排由独立工具或WORK-LAB承担，AAOS不在本轮变成完整IDE/Agent平台。

Asta、PaperQA2、OpenScholar、Intern-S2、端砚等仅来自历史能力原文与候选线索。本轮没有重新核验其维护、许可、原生MCP或真实安装条件。保持候选身份，接入时查官方源和现行版本。

## 每项未来能力的说明至少包含
原需求引用；人类/AI/共用及所属环节；承载界面/活动；输入与输出；候选接入方式与方向；前提/依赖/权限/预算；难度与阶段；当前缺口/状态来源；替代方案；启动条件；具体验收证据。
同一条目可以既有当前可用部分，又有未来部分，不能整族灰掉或整族标可用。
