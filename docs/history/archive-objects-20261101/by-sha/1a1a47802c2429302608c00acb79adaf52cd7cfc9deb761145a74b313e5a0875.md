## 1. 这个项目的本质拆解

你不是在做一个普通插件，也不是在做一个主题。你做的是：

**Obsidian 内的“知识库操作台”。**

它的价值不在于重新写 Markdown、搜索、文件树、双链，而是在于把你自己的学习流程重新组织成一个固定的生产力界面：

```text
课程输入
  ↓
课程卡片
  ↓
证据核验
  ↓
主动复习
  ↓
项目转化
  ↓
执行日志
  ↓
下一步行动
```

所以 OBS 前端真正要解决的是：

1. 入口太散；
2. 课程资料和学习动作脱节；
3. 证据、复习、项目、日志没有统一关系；
4. Obsidian 原生界面强，但不够像你的“个人知识 OS 控制台”。

你的文档里提出的“Obsidian 内核 + OBS 前端使用层 + 学习/证据/复习/项目工作流”就是正确总架构。fileciteturn2file0

---

## 2. 最合理的软件架构

推荐采用 **四层结构**：

```text
第一层：Obsidian Core
负责：Markdown、Vault、文件树、双链、搜索、Canvas、Graph、命令面板、插件生态

第二层：OBS Frontend Plugin
负责：总控台、模块导航、状态卡片、工作台界面、入口按钮、Inspector、底部状态栏

第三层：Lightweight Index
负责：课程索引、证据索引、复习索引、项目索引、日志索引、模块映射

第四层：Optional Automation / HERMES Contract
负责：批量导入、课程解析、AI 总结、同步、外部任务执行、后端契约
```

这四层里，**第一层永远是主权层**。Obsidian 本身用 Vault 存储 Markdown 文件，本地 Vault 是文件夹，笔记是 Markdown 纯文本，这说明你的“本地优先、不破坏 Vault”的路线是合理的。citeturn576166view1

## 3. 哪些能力必须留给 Obsidian

这些不要重做：

| 能力 | 是否重做 | 原因 |
|---|---:|---|
| Markdown 编辑 | 不重做 | Obsidian 已经成熟 |
| 文件树 / Vault | 不重做 | 这是底层资产，不要破坏 |
| 双链 / 反链 | 不重做 | OBS 只做入口和关系展示 |
| 搜索 | 不重做 | 调用原生搜索或链接 |
| 快速切换 | 不重做 | 保留 Obsidian 操作习惯 |
| 命令面板 | 不重做 | OBS 按钮可触发命令 |
| Canvas | 不重做 | OBS 可以生成/打开 Canvas，但不要自造低质量 Canvas |
| Graph / 局部图谱 | 不重做 | OBS 只做状态入口或局部映射 |
| 插件生态 | 不重做 | 借力，不绕开 |

你的文档也明确说 OBS 前端应该调用 Obsidian 能力，而不是重新造一套低质量替代品。这个原则一定要保留。fileciteturn2file0

## 4. 哪些能力适合放进 OBS 前端使用层

OBS 前端应该做 **组织、导航、状态、工作流**，不是做底层存储。

适合放进 OBS 前端的能力：

| 模块 | OBS 应该做什么 |
|---|---|
| 总控台 | 展示当前模块、索引状态、安全边界、最近入口 |
| 课程指挥舱 | 课程卡片墙、课程入口、学习路径、缺口队列 |
| 证据矩阵 | verified / pending / reference / missing 状态 |
| 主动训练中心 | 复习队列入口、主动回忆入口、错题复盘入口 |
| 项目推进台 | 课程转项目、项目卡片、交付物、阻塞点、下一步 |
| 执行日志 | 导入报告、自动化记录、恢复点、阻塞记录 |
| 前端设置 | 视觉系统、索引状态、禁止动作、命名边界 |

你现在已有 7 个模块入口、固定左侧菜单、顶部工作区标签、右侧 Inspector 和底部状态栏，这说明前端壳层已经不是从零开始，而是已经进入“接真实数据入口”的阶段。fileciteturn2file0

## 5. 轻量索引层应该怎么设计

你现在的 `obs-frontend-map.json` 和 `obs-course-index.json` 是正确方向，但建议拆成更清晰的 **5 类索引**：

```text
.obsidian/plugins/talos-frontend-ui/data/
  obs-frontend-map.json       # 模块入口映射
  obs-course-index.json       # 课程索引
  obs-evidence-index.json     # 证据索引
  obs-review-index.json       # 复习索引
  obs-project-index.json      # 项目索引
  obs-execution-log.json      # 执行日志索引
```

第一阶段不要上数据库。  
原因：你现在的数据不是大规模结构化业务数据，而是 **Obsidian 文件入口 + 状态映射 + 工作流索引**。JSON 足够，简单、可控、容易回滚，也符合“不扫描整个 Vault”的边界。

长期可以这样分层：

```text
Markdown / Vault = 真实内容源
JSON Index = 轻量入口索引
SQLite = 可选缓存，不做真源
后端服务 = 后期自动化，不直接控制 Vault
```

也就是说，**数据库最多做缓存和查询加速，不能做唯一真源。**

## 7. 不扫描整个 Vault，怎么建立课程索引

正确做法是 **显式登记 + 局部索引 + 手动确认**。

不要让插件启动时全 Vault 扫描。Obsidian 官方插件性能建议里也明确提到，插件启动时不要在 `onload` 里做昂贵计算或数据获取；如果需要启动后逻辑，应放到 `onLayoutReady` 之后。citeturn576166view0

推荐流程：

```text
第一步：指定课程入口根目录
例如：02_课程卡片墙

第二步：只读取 obs-course-index.json
不扫 Vault，不读正文

第三步：前端显示已登记课程
点击后用 Obsidian 原生链接打开

第四步：新增课程时手动登记路径
或者后期提供“授权扫描指定文件夹”按钮

第五步：索引校验只检查路径存在性
不分析正文，不改文件内容
```

也就是说：

```text
允许：检查 index 里写好的路径是否存在
禁止：启动时遍历整个 Vault
禁止：读取所有课程正文
禁止：自动改课程内容
```

你现在已经用 `openLinkText` 打开 `02_课程卡片墙`，这个方向对。Obsidian 官方开发示例里也使用 `app.workspace.openLinkText(...)` 来打开文件链接，这说明你的接入方式是合理的。citeturn803655view1

## 8. 界面高级但不卡，应该这样控制

你的视觉方向是“深色 Command Console + 紫晶高亮 + 类浏览器外壳 + 中心星轨/节点/Canvas 式主画布”。这个可以做，但要克制。fileciteturn2file0

性能原则：

```text
1. 左侧菜单、顶部栏、右侧 Inspector、底部状态栏常驻
2. 中间内容区按模块切换
3. 每次只渲染当前模块
4. 首页最多展示摘要，不展示全部课程
5. 星轨节点最多展示 7 个主模块，不展示全部知识点
6. 大图不进 main.js
7. 动画只用 CSS transform / opacity
8. 不用复杂 canvas 粒子背景
9. 不在 onload 里读数据
10. JSON 数据按需读取
```

Obsidian 官方文档提醒，未过滤的数据视图可能会涉及大量文件，视图应能处理数千条数据、复用 DOM、避免渲染屏幕外内容。这个原则非常适合你现在的 OBS 前端。citeturn803655view1

## 9. 分阶段落地顺序

### 第一阶段：把壳层做稳

目标：不是加功能，而是让 OBS 前端在 Obsidian 内稳定打开。

必须完成：

```text
- 插件打开稳定

- 顶部标签固定

- 底部状态栏能显示索引状态
- main.js 小体积
- CSS 独立
- JSON 数据独立
```

不要急着做：

```text
- AI 自动总结
- 全 Vault 扫描
- 数据库
- 复杂图谱
- 炫酷大动画
```

---

### 第二阶段：课程指挥舱真实接入

目标：先把课程入口打通。

做：

```text

```

不做：

```text
- 不计算虚假进度

```
