## 1. 先定加强目标：OBS-AS 不做“笔记软件”，做“知识处理系统”

现在的 OBS-AS 不应该跟 Obsidian 本体竞争，而应该做 Obsidian 的增强层：

**核心定位：**

> 把任意课程、PDF、视频、音频、图片、网页资料，转成可验证、可复习、可双链、可检索、可项目化的 Obsidian 知识资产。

也就是说，它要解决五件事：

1. **资料接入**：课程、PDF、视频、音频、截图、网页、文档。
2. **证据提取**：OCR、ASR、PDF 页图、视频关键帧、原文片段。
3. **知识生成**：课程笔记、概念卡、问题卡、流程图、Canvas、复习卡。
4. **本地核验**：先查本地证据，再决定是否联网补证。
5. **安全写入 Vault**：所有输出先 dry-run，再人工确认写入。

你现在已经有 V4–V9 的脚本分层，比如 V4 安全写入、V5 内容多样化、V6 真实证据/PDF/视频关键帧、V7 项目化、V8 训练复盘、V9 OER 交叉对比。这个方向对，但还没产品化。citeturn510112view1

## 2. 第一优先级：把后端从“脚本集”升级成“稳定处理引擎”

现在后端最大问题不是功能少，而是**缺少统一入口、统一配置、统一任务状态、统一日志**。

应该新增一个核心层：

```text
obs_as_core/
├─ config/
│  ├─ obs_as.config.yaml
│  └─ pipeline_profiles.yaml
├─ core/
│  ├─ task_runner.py
│  ├─ vault_resolver.py
│  ├─ evidence_store.py
│  ├─ course_manifest.py
│  └─ write_guard.py
├─ pipelines/
│  ├─ ingest_pdf.py
│  ├─ ingest_video.py
│  ├─ ingest_audio.py
│  ├─ ingest_image.py
│  ├─ build_course_pack.py
│  └─ build_review_cards.py
└─ cli.py
```

这样以后不是到处运行：

```bash
python scripts/v6/pdf_page_snapshot.py ...
python scripts/v6/video_keyframe_extract.py ...
python scripts/v5/generate_course_review_cards.py ...
```

而是统一成：

```bash
obs-as ingest --source "D:/课程/物理课.pdf" --course "高中物理-密度"
obs-as build-course --course "高中物理-密度" --dry-run
obs-as verify --course "高中物理-密度"
obs-as apply --course "高中物理-密度" --vault "E:/BaiduSyncdisk/Obsidian知识库"
```

你现有 `course_verify.py` 已经有本地证据库思路，用 SQLite 建库，但查询逻辑还是把 chunks 全部取出再在 Python 里打分排序，后期课程库一大就会慢。下一步应改成 **SQLite FTS5 全文索引 + 增量更新**。citeturn106834view0

## 3. 第二优先级：保留安全底座，但做成“写入闸门”

这是你项目里最值钱的一块，不能丢。`safe_vault_writer.py` 已经做了 dry-run、显式 `--apply`、禁止删除、覆盖前备份、路径穿越拦截。citeturn106834view1

但现在它只是一个脚本/库，应该升级成整个系统的**唯一写入通道**。

建议规则：

```text
任何内容不得直接写入正式 Vault
↓
必须先进入 staging/
↓
生成 write-plan.json
↓
生成 write-preview.md
↓
通过 verifier 核验
↓
人工确认
↓
safe_vault_writer apply
↓
生成 write-report.md
```

也就是说，后面无论是 Hermes、Codex、DeepSeek、Copilot 还是本地脚本，都不能绕过这个写入闸门。

新增目录：

```text
.obs-as/
├─ staging/
├─ reports/
├─ backups/
├─ manifests/
├─ evidence/
├─ logs/
└─ task_state.sqlite
```

这样你就能做到：**AI 可以生成，但不能乱写；脚本可以处理，但不能误删；出错可以回滚。**

## 4. 第三优先级：补“证据链系统”，不要只生成漂亮笔记

你一直觉得课程总结“苍白”，根本原因是：现在大多数 AI 笔记只是总结文本，不是真正绑定证据。

OBS-AS 应该强制所有知识点带证据来源：

```yaml
---
course: 高中物理-密度
source_type: pdf_page/video_keyframe/asr/ocr/manual
source_file: density_lesson.pdf
source_page: 12
evidence_status: verified
confidence: 0.86
generated_by: obs-as
review_status: pending
---
```

每个知识点最好生成四类内容：

```text
1. 原始证据：PDF 页图 / 视频关键帧 / OCR / ASR 原文
2. 知识解释：概念、公式、步骤、案例
3. 学习加工：问题卡、复习卡、错题卡、类比解释
4. Obsidian 结构：双链、标签、Canvas、Dataview 字段
```

你 V6 里面已经有 PDF 页图、视频关键帧、metadata、证据索引思路，应该把它变成强制标准。README 里也已经明确 candidate-only 不能自动升级成 verified，这个原则要继续强化。citeturn510112view1

建议新增三个状态：

```text
candidate-only：只是候选证据，不能写进正式知识点
single-source：单一来源支持，可以保守写入
verified：多来源或人工确认，可以进入正式库
```

## 5. 第四优先级：把前端从“UI 原型”升级成真正 Obsidian 插件

```text
obsidian-obs-as-plugin/
├─ manifest.json
```

Obsidian 官方 manifest 要求插件包含 `id`、`name`、`version`、`minAppVersion`、`description`、`author`、`isDesktopOnly` 等字段，所以你后面不要继续只写静态 HTML，要按正式插件工程走。citeturn304399view1

前端最应该做 5 个页面：

| 页面 | 作用 |

| Course Reader | 阅读课程、查看 AI 笔记、原始证据并排显示 |
| Evidence Matrix | 每个知识点对应哪些 PDF 页、OCR、ASR、关键帧 |
| Review Cards | 自动生成复习卡、错题卡、问题卡 |
| Pipeline Monitor | OCR/ASR/关键帧/写入任务状态 |

这样打开 Obsidian 后才会像一个真正的“知识工作台”，而不是一堆文件夹和脚本。
