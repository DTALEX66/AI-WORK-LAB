## 目前最接近你需求的：Omnigent

urlOmnigent GitHubhttps://github.com/omnigent-ai/omnigent

它目前原生覆盖：

**Claude Code / Codex / Cursor / OpenCode / Hermes / Pi / OpenAI Agents SDK / 自定义 Agent**，并允许一个 Supervisor Agent 调用子 Agent、让不同 Agent 互相审核，还能加 MCP 工具、沙箱、权限控制和成本限制。citeturn145286search0turn145286search5

甚至可以这样定义一个 Agent：

```yaml
name: project_architect

prompt: >
  审计整个项目，分析架构、未完成任务和技术债，
  生成执行计划，然后将任务分派给执行Agent。

executor:
  harness: openai-agents

tools:

  codex:
    type: agent
    executor:
      harness: codex

  hermes:
    type: agent
    executor:
      harness: hermes

  dsh:
    type: mcp
    url: http://127.0.0.1:xxxx/mcp
```

也就是说以后你输入：

> 全量审计 AAOS，找出架构问题、BUG、未完成模块，制定最短闭环方案并执行。

顶层 GPT 可以：

```text
GPT Supervisor
      │

      ├─ 任务拆解
      ├─ 风险判断
      │
      ├──► Codex
      │      └─ 修改核心代码
      │
      ├──► Hermes
      │      └─ 调研 / 测试 / 辅助执行
      │
      └──► DSH
             └─ DeepSeek并行子Agent
```

然后结果重新回来：

```text
GPT Supervisor
      ↓

      ↓
```

```bash
hermes mcp add codex --preset codex
```

官方文档明确给出了这个方式，本质就是：

```text
Hermes
   │
   └── MCP
        │
        └── Codex CLI
```

> 审计项目，然后把代码实现任务交给 Codex。

```text
Hermes
├─ OpenAI / Codex
├─ DeepSeek
├─ Gemini
├─ Claude
├─ Qwen
├─ MiniMax
├─ OpenRouter
├─ Ollama
├─ LM Studio
├─ 本地模型
```

DeepSeek 已经是 Hermes 的原生 provider。citeturn214260search0turn214260search10


把**自己变成 MCP Server**，供其他顶层 Agent 调用。citeturn483858search2

# 唯一需要纠正的是：“网页端 GPT”

这里最好**不要设计成**：

```text
软件
 ↓
打开 chatgpt.com
 ↓
模拟鼠标键盘
 ↓
让网页GPT规划
 ↓
复制结果
 ↓
打开Codex
```

虽然通过 Browser Agent / Playwright / Computer Use technically 能实现，但这会非常脆弱：

```text
网页改版
登录状态
验证码
页面加载
上下文同步
按钮变化
超时
浏览器崩溃
```

都会破坏工作流。

真正稳定的结构应该是：

```text
GPT能力
   │
   ├─ OpenAI Agents SDK
   ├─ Agents API
   └─ Codex Harness
```

OpenAI 现在官方 Agents 架构已经支持多 Agent、handoff、MCP、工具、沙箱和长任务；Agents API 本身运行 Codex harness。citeturn483858search3turn483858search6

而 Codex 本身可以直接使用你的 **ChatGPT 账户登录**，消耗 ChatGPT 计划里的 Codex 用量，而不是必须 API Key。citeturn643936search8turn643936search12

所以应该是：

```text
错误方向：

WORK-LAB
  ↓
Chrome
  ↓
ChatGPT网页版
  ↓
Codex


更好的方向：

WORK-LAB
  ↓
GPT Supervisor
OpenAI Agents SDK
  ↓
Agent Router
  ├─ Codex ChatGPT OAuth
  ├─ Hermes
  ├─ DSH
  ├─ Gemini CLI
  └─ Claude Code
```

# 对你的三个项目，我反而不建议再造“第四套大软件”

我现在会把架构调整成：

```text
                     AAOS
            知识 / Memory / Skill
                      ▲
                      │
                      │
┌─────────────────────┴────────────────────┐
│               WORK-LAB                  │
│                                         │
│          Agent Control Plane            │
│                                         │
│   Planner → Router → Executor → Review  │
│                                         │
│  Omnigent / MCP / ACP / Agents SDK      │
└───────────┬──────────┬──────────┬────────┘
            │          │          │
          Codex      Hermes      DSH
            │          │          │
          GPT       DeepSeek   DeepSeek
            │
            └──────────────┐
                           ▼
                      DESIGN-LAB
                    设计软件 / 执行
```

也就是说：

**WORK-LAB 不需要重新发明 Agent Runtime。**

让：

```text
Omnigent = Agent Runtime / Meta Harness

MCP = 工具总线

ACP = Agent 客户端协议

OpenAI Agents SDK = GPT Supervisor

Codex = 代码专家

Hermes = 通用自主 Agent

DSH = DeepSeek 执行集群

AAOS = 长期知识 / 技能 / 记忆中枢

DESIGN-LAB = 设计执行层

WORK-LAB = 用户看到的唯一顶层入口
```

这样你的 WORK-LAB 才真正变成 **AI Control Plane**，而不是“另一个 Agent 软件”。
