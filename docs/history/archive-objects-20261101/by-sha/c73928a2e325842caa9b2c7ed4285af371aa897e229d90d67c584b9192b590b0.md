### 1. WORK-LAB：已经够用，但还不该叫“最终完成”

最新 `main` 已受保护，最近的 [CI 全绿](https://github.com/DTALEX66/WORK-LAB/actions/runs/31803204309)，也已经有 Observer Native v0.1.0 Release。

但仓库自己的当前状态仍明确列出：

- `hermes_live_apply` 未验证
- `real_device_validation` 未验证
- `commercial_release` 未验证
- 真实运行时 checkout/CI attestation 仍需运行环境
- 仓库还残留旧 `OPEN-DESIGN-Assistance`、`open-design` topic 等命名漂移
- 分支和历史任务包很多，容易重新膨胀

因此 WORK-LAB 不需要继续“大建设”，只需完成一次基础版关账：

1. 在 Windows 本机验证三个项目根目录识别准确。
2. 验证 Hermes、Codex 多项目并行时 Observer 不把子模块误判成主体项目。
3. 验证只读观测不会修改项目数据库、Git、任务状态。
4. 跑通便携启动、Sidecar、SSE、重启恢复。
5. 清除活动文档和仓库 metadata 中的旧项目命名。
6. 固定一个 `WORK-LAB Foundation` 基线版本，然后冻结功能扩张。

完成这些后，WORK-LAB 转入“只修真实问题”的维护模式。

## 2. 为什么必须先完成 ArcheAxis Knowledge

这是目前最短路径能形成完整用户产品的项目。

它已经具备：

- Python + FastAPI + SQLite + Tauri 技术主体
- PDF 导入、阅读、渲染和证据批注
- OCR/媒体基础处理
- Evidence、Knowledge、Learning、Machine Knowledge 基础对象
- 导出、备份、校验、恢复
- React/Vite App Shell 骨架
- Windows、NSIS、Green/Portable 构建代码
- 最新 [CI 已恢复全绿](https://github.com/DTALEX66/ArcheAxis-Knowledge-OS/actions/runs/31817485631)
- 已有 [v0.5.0 Release](https://github.com/DTALEX66/ArcheAxis-Knowledge-OS/releases/tag/v0.5.0)

现在的问题已经不是“有没有架构”，而是：

> 代码能力很多，但还没有收束成用户打开就能完整使用的一条产品主线。

因此 OS 接下来不要再继续吸收大量开源项目，也不要继续扩大 H6—H10 蓝图，而是只完成发布主链：

1. 统一唯一桌面 App Shell，处理 `OSUI`、`frontend`、根 `index.html`、旧工作区 UI 多入口问题。
2. 首次启动选择五个外置区域：
   - 证据库
   - 原件库
   - 人类学习知识库
   - 机器学习知识库
   - 外置依赖/环境/组件/插件库
3. 跑通真实材料闭环：
   - 导入
   - 原件保全
   - 转换
   - 阅读/编辑
   - 证据锚定
   - 人类知识
   - 机器知识
   - 导出/备份
   - 重启读回
4. 用真实 Windows 安装包完成点击级验收。
5. 完成绿色版、便携版、安装版三种交付。
6. 冻结并发布一个真正可日常使用的 v1.0。

一旦这个闭环完成，你就拥有第一个真正能每天使用的核心产品，而不是第三个继续扩大的研发仓库。

## 3. DESIGN-LAB 为什么必须第三

DESIGN-LAB 当前规模最大：

- 3112 个文件
- 约 170 MB 当前树内容
- 1583 个 Markdown 文件
- 大量第三方设计知识、Skill、参考实现和 MiniGame fixture

但机器状态非常诚实：

- Design Intelligence：E1
- Visual Quality：E1
- Professional Domains：E1
- Production Handoff：E1
- Creative Toolchain：E1
- Style Master Method：E0
- E3 真实 Host 运行未完成
- E4 Release 未完成
- E5 商业验收未完成
- `main` 当前未保护
- 尚无正式 Release

也就是说：

> DESIGN-LAB 是“能力地图很完整”，不是“能力已经真实工作”。

如果现在先主攻它，极易继续增加 Adobe、ComfyUI、MiniMax H3、Figma、Blender、各种设计 Skill 和资料，却迟迟没有一个真实商业任务从 brief 跑到可编辑交付。

它以后应以一个纵向闭环启动，而不是继续补全所有设计领域。最适合你的第一条闭环是：

```text
真实客户 Brief
→ 商业设计方向
→ 主视觉
→ 平面/电商应用
→ Photoshop 可编辑文件
→ 视觉质量人工评审
→ 生产预检
→ 可编辑交付
→ 客户/设计师验收
```

做到这条 E3/E4 后，再扩展包装、空间、3D、视频、游戏设计。

另外，当前文件中的 `Open Design` 必须重新定性：如果它是参考宿主，就只能作为独立 Host Adapter 名称；不能继续让人误解成 DESIGN-LAB 的旧项目身份。

## 最终执行顺序

### 阶段 A：WORK-LAB 基础关账

只解决真实运行、项目根识别、Observer 准确性、Windows 便携验证和旧命名，不再增加新功能。

### 阶段 B：ArcheAxis Knowledge v1.0

这是第一个真正要“完成”的项目。资源投入建议：

- OS：80%
- WORK-LAB 维护：15%
- DESIGN-LAB 冻结维护：5%

### 阶段 C：DESIGN-LAB 商业纵切

暂停继续吸收设计资料，先把现有 E1 能力提升成一个真实 E3/E4 商业设计闭环。

## 一句话定案

> **先关账 WORK-LAB，但第一个正式完成的产品必须是 ArcheAxis Knowledge；DESIGN-LAB 等 OS v1.0 后再集中完成第一条商业设计生产闭环。**

最不应该采用的顺序是“先把 DESIGN-LAB 所有设计领域和资料补全”，因为它目前范围最大、运行证据最弱，也最容易永远无法定义完成。
