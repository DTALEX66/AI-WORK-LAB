**六、WL-CC 超级入口与 LAB Router**

保留原文档 WL-CC-01～08。

四个核心表面：

- Home：工作总览与继续入口。
- Quick Entry：搜索、命令、自然语言意图与动作预览。
- Control：获准的写操作。
- Observer：严格只读的状态与审计。

Router 复用现有对象，收敛以下能力：

- Capability Registry。
- Intent Resolver。
- Action Router。
- Context Broker。
- Permission Broker。
- Status Aggregator。

核心协议版本化：

Capability、Intent、Action、Context、Permission、Approval、ResultRef、EvidenceRef、Resource、Runtime、Health/Status。

Action 至少包含：

trace_id、actor/origin、target project、capability、params、context refs、permission decision、approval ref、result/error、receipt refs、timestamps。

未知 capability、无效参数和不支持的 schema 按契约拒绝；高风险动作 fail closed。

Quick Entry 流程：

1. 搜索或解析用户输入。
2. 显示目标项目、任务、动作与资源。
3. 按动作需要选择执行器、Provider 和模型。
4. 展示权限结果及必要的变更预览。
5. 高风险动作经 Approval。
6. 由目标 Adapter 执行。
7. 返回 ResultRef/EvidenceRef/receipt。
8. Observer 读回状态。

确定性命令优先规则匹配，不为每次搜索调用 LLM。含糊意图展示候选；模型生成的文本不能直接变成任意 Shell 命令。

三条真实场景必须通过：

- 继续 ArcheAxis 当前任务。
- 运行 WORK-LAB 任务或查看/控制 Runtime。
- 继续 DESIGN-LAB 当前项目。

系统级快捷键、托盘和外部 Launcher 属于可选接入层。PowerToys Command Palette 等不能成为任务、权限或 Router 真值。

网页端规划交接先实现：

导出项目上下文与任务引用 → 用户在网页端处理 → 导入规划结果 → 校验结构与基线 → 用户选择执行器 → 执行与回执。

导入结果不能绕过权限；不得假定网页订阅额度等于可调用 API。

**七、WL-MODEL 主 Runtime 与共享模型治理**

本轮实施首选：LM Studio。

依据是个人桌面操作、API/CLI 自动化与后台运行的综合适配，不代表已经实测它速度最快。

部署原则：

- 先检查已有 LM Studio、Ollama、llama.cpp 或其他 Runtime。
- 不为采用推荐方案破坏现有稳定服务。
- 本轮不新增 Ollama 或独立 llama-server 作为常驻副本。
- LM Studio 内部推理后端不等于需要额外部署独立服务。
- Lemonade、Jan、Xinference、LocalAI 等保留为有条件备选；只有出现具体硬性缺口时重新评估。
- OCR/ASR/Reranker 不强行全部塞进 LM Studio；必要时使用最小专用 worker，统一登记治理。

唯一物理模型库：

D:\All projects\Model library

治理链：

Physical Model → Runtime → Provider → Capability → Project Permission

执行顺序：

Inventory → Hash → Identify → Reuse → Missing → Download

不扫描全盘；仅检查获准模型库和已登记资源路径。先核验已有文件，不因“没找到”立即下载。

模型导入前核实：

- 是否复制、移动、链接或仅引用现有文件。
- 导入后的真实路径、Hash 与新增占盘。
- 删除/升级会影响哪些引用。
- 分片、Tokenizer、配置和辅助文件是否完整。

同一个根目录不自动等于同一份物理资产。权重不得进入 Git，缓存进入 WORK-LAB machine/runtime local area。

**八、WL-MODEL-09～13 性能与 Golden Tests**

记录真实：

- 冷/热启动与加载时间。
- RAM、VRAM、CPU/GPU 使用。
- TTFT、prompt tok/s、generation tok/s。
- 实际上下文、输出长度、量化、后端版本与运行参数。

- CPU+GPU hybrid 的实际体验。

4K/8K/16K 按资源条件逐步验证，无法支持的档位如实记录，不强行跑到系统失稳。

Golden Set：

- FAST：分类、metadata、简单抽取、query rewrite、短问答、路由。
- DEEP：复杂知识、多文档综合、长上下文、推理与候选生成。
- OCR：中文、英文、混排、扫描 PDF、图片、表格、页序与 provenance。
- ASR：真实中文、时间码、标点、噪声、长音频。
- Embedding：维度、batch、检索质量、超时与重启。
- Reranker：排序契约、真实 retrieval chain、超时与重启。

测试前记录可接受阈值与依据；阈值建议和用户已确认要求分开。报告质量与速度两方面结果，不只追求 tokens/s。

**九、WL-E2E/INTEG 三项目真实闭环**

**十、WL-SEC 权限、安全与恢复**

- Observer 只读；不持有写 credential，不复用 Control mutation handler。
- 隐藏按钮不算权限隔离，API 层必须拒绝越权。
- Control mutation 经过 Permission；高风险操作绑定明确的 Approval 范围。
- UI 不直接执行任意外部命令；由受控 Adapter/Executor 完成。
- 同一资源只有一个 writer；并行任务分配目录、接口与写入边界。
- 审计记录 trace_id、actor、target、decision、approval、Provider/Runtime、result/error、receipt 与时间。
- 日志脱敏，默认不持久化用户完整原文或凭据。
- 注册信息重启后可读回；任务中断状态可解释，不盲目重放可能重复写入的动作。
- 重复模型与过时缓存先列清单，实际删除需核实 Hash、引用、活动进程、回滚方式和授权。
