Gitee 这里确实不像 GitHub 那样明显显示**个人空间总容量 / 仓库占用大小**，很多用户都会找不到。

你可以几个方式查看：

---

## 方法1：查看单个仓库大小（网页端）

进入你的仓库：

```
仓库主页
→ 文件
→ 管理
→ 仓库设置
```

部分版本会显示：

- 仓库大小
- Git LFS 使用量
- 存储统计

但 Gitee 不同版本界面位置可能变化，有些个人仓库不会直接展示。

---

## 方法2：用 Git 命令查看（最准确）

克隆仓库：

```bash
git clone https://gitee.com/用户名/仓库名.git
```

进入：

```bash
cd 仓库名
```

查看 Git 历史大小：

```bash
git count-objects -vH
```

会看到：

例如：

```
size-pack: 850 MiB
size: 120 MiB
```

其中：

- size-pack = 历史压缩对象大小（主要占用）
- size = 松散对象大小

---

## 方法3：本地查看仓库实际大小

Windows：

右键仓库文件夹：

```
属性
```

但是注意：

```
.git
```

你的项目：

例如 AAOS：

```
AAOS
├── src
├── assets
├── models
├── docs
└── .git

真正影响仓库大小的是：

```
.git

- 强烈建议 < 5GB

  - GitHub 不允许直接 push

Git LFS

免费1TB

# 一、为什么 GitHub CI 会慢？

GitHub Actions 慢，一般不是 GitHub 本身慢，而是：

```
提交代码
 ↓
启动Runner
 ↓
拉取仓库
 ↓
安装依赖
 ↓
编译
 ↓
测试
 ↓
安全扫描
 ↓
上传Artifact
```

每一步都可能拖慢。

# 原因1：仓库历史太重（最可能）

Git 最大的问题：

不是当前文件大小。

而是：

```
.git
```

里面保存：

- 所有commit
- 删除过的文件
- 修改历史
- 二进制历史


例如：

你现在：

```
AAOS

以前：
assets/
  设计稿.psd 800MB

后来删除

现在仓库：
代码只有200MB

但是.git：
可能还有800MB
```

因为 Git 不会自动删除历史。


GitHub官方也明确建议：
大型仓库会降低 clone、fetch 和 CI 性能，推荐控制仓库规模，并把大型二进制文件移出 Git，使用 Git LFS 或对象存储。citeturn0search1
