请为 WORK-LAB（工作流实验室）完成“第一总阶段 UI”：统一桌面外壳、设计系统、核心任务页面、主要跳转和必要状态。请直接开始设计，完成下面全部交付，不只给首页、单张概念图或文字建议。

一、产品理解：先明确用户如何使用

WORK-LAB 帮助个人用户管理和用好 AI 工作环境：整理软件、模型服务、插件、规则、配置与工作流的方法；观察运行状态；汇总阻塞问题；提供使用建议与可复制的修复交接材料；核验外部处理结果；保存并复用有效方案。

用户在“使用之前”可以找配置方法与工作流方案；“使用过程中”可以看状态、用量与需要关注的问题；“出现问题”可以准备材料交给自己选择的外部 Agent；“处理之后”可以核验并积累方案。不能把产品画成只看指标的监控大屏。

实际开发、执行和修复由 Codex、Qoder、WorkBuddy 等外部工具完成。WORK-LAB 不成为 Agent，不新建聊天机器人、模型网关、工作流执行器、节点画布或跨项目上下文总管。当前独立运行，不依赖 DESIGN-LAB 或 AAOS，不设计 AAOS 入库或互联流程。

第一总阶段设计完整目标体验，但这只是 UI 方案与原型，不证明后端已接通。现有后端已有部分问题汇总和修复包导出；通用方案库、完整结果回收与前端接线仍有缺口。请在画板外的设计注释标“已有基础／待接入／拟新增”，不要把工程状态和合同说明堆进普通用户页面。

二、视觉方向：轻量、成熟、有质感

这是 Windows 桌面工具，不是营销网站。设计中文界面。整体像一件安静、精确的专业桌面工具：苹果玻璃外壳、冷珍珠白、清楚文字、细边线、克制阴影和足够留白。

主稿使用冷珍珠白：背景 #F4F6F8，正文表面 #FFFFFF，主文字 #202630，次文字 #5D6876，分隔线 #DFE4EA，唯一品牌强调色 #356C97。深色变体用背景 #171B20、表面 #222830、主文字 #E8EDF3、次文字 #A5AFBC、分隔线 #39424D；强调色维持同色相。成功、注意、失败允许独立语义色，但不可用它们装饰整页。

玻璃只用于侧栏、顶部外壳、HUD 和临时浮层，正文与长列表使用稳定实底。玻璃后没有复杂彩色背景；提供关闭透明效果后的清楚版本。不要为了质感做大面积实时模糊、连续动画或发光。

字体优先 Segoe UI Variable／Segoe UI，中文 Microsoft YaHei 或本地无衬线字体，不依赖下载远程字体。正文14–16px，次要标签至少12px，页面标题22–26px。按钮圆角6–8px，普通表面10–12px，浮窗外壳16–20px。用字重、间距与对齐建立层级，不用巨大标题和大量卡片。品牌文字准确使用WORK-LAB／工作流实验室；有现成标识则沿用，没有附件时仅用简洁字标，不重新发明LOGO。

禁止：紫蓝霓虹、AI 渐变球、聊天欢迎屏、控制塔、密集仪表盘、巨大 KPI、套娃卡片、满屏英文枚举、无意义波形、持续呼吸灯和无限动效。不要做纯概念海报或外部场景样机，要正面完整软件画板。

三、统一桌面外壳与导航

主窗口以1280×820设计，提供1920×1080扩展验证与900×600紧凑布局。主内容应随空间重新排布，不能简单把整张画板等比缩小，也不能裁掉两侧。Windows 窗口控制位于右上角，使用 Ctrl 快捷键，不放 macOS 红黄绿按钮或 Command 标记。

左侧主导航仅四项：工作台、软件与能力、方案库、记录。设置固定底部。侧栏约196–212px；顶栏44–52px。收起侧栏后仍有名称提示。顶栏保留当前页标题、搜索入口和“桌面浮窗”；不要增加第二排全局导航。

主体以一张清楚列表或一份详情为中心。只在需要时打开一个右侧详情面板，不同时挤入两侧工具栏、底部控制台和三个内容列。主要内容留24–32px内边距。每个状态最多一个最突出的主操作，其他动作用文字按钮或更多菜单。

软件、Agent、模型服务、插件、技能、规则、集成、隔离试用与专业接口归入对应软件详情。问题、交接和核验属于同一条处理流程。日志、摘要值、原始证据和接口技术细节放在可展开区域，保留能力但不全部做成主导航。

四、第一阶段必须设计的10个画板

W01 工作台
回答“我现在有哪些工作、哪里需要处理、下一步是什么”。顶部只放一条简洁状态摘要，不做三到六张 KPI 卡。主体是项目／工作列表及需要处理的问题；项目行显示项目名称、参与软件、工作状态、主要阻塞、最近证据时间。工作状态与观测状态分开。
问题行显示可读标题、影响范围、所属软件、重复次数、更新时间、下一步。点击后进入 W03。常态下可展示最近使用的方案和软件变化，避免首页只在故障时才有价值。未接入来源给“尚未接入”与查看设置的路径，不能画成“0个问题，一切正常”。

W02 软件与能力
左侧或上方为软件列表，点击打开同页详情。软件详情先展示身份、版本、最近观测时间与可确认的能力。分别表达“已登记、已安装、已连接、实际调用有证据”，不要一个绿点概括全部。
二级分栏最多四项：概况、使用与方案、规则与扩展、接口与验证。插件／技能、模型服务、专业适配、隔离试用及迁移比较收在这些分栏或展开区。支持用户找“这个软件怎么配置／有哪些适用方案”，不只是看日志。采集停止、数据过期、软件退出和未接入必须分开。
开源来源信息放在能力或方案详情内：来源、版本、采用方式、适用条件、验证状态。收录、借鉴方法、已安装、实际可用不是同一种状态；不另建一个占首页的大市场。

W03 问题详情
头部是用户读得懂的问题标题，一句话解释影响；主体依次是“发生了什么／已有证据／建议下一步”。展示项目、软件与版本、首次与最近发现、重复次数，证据默认只露关键片段。优先呈现匹配的历史方案；没有可靠方案时引导“准备交接材料”。右侧高级信息默认关闭。
区分问题所属软件和处理执行者，禁止自动把出错的软件当作负责修复的软件。不要在这里放批准、重试、执行、应用配置或直接关单按钮。

W04 交接材料预览
显示关联问题、项目和选定的外部执行工具。执行工具由用户选择，支持明确的“人工复制交接”，不假装每种工具都有原生调用接口。没有数据时说明尚未验证，不画“已连接”。
正文展示问题摘要、关键证据、允许处理范围、限制、已有尝试、验收方法和恢复说明；模板缺失内容有具体提示。主操作“复制交接材料”，次操作“下载材料”。复制后提示“已复制，尚未发送”，不要显示任务已执行。未知验证命令写“需要补充验证方法”，不要编造命令。
用户希望登记已交接时，打开独立的“确认记录”控制面，绑定当前问题和材料版本；不要在只读观察页面直接写业务状态。

W05 外部结果与核验
按阶段清楚展示：用户记录已交接、外部工具声称完成、待核验、核验通过或未通过。完整分阶段记录收进展开区，不用满屏流水线。
设计“导入处理结果”的独立控制面，显示材料身份、项目、版本和证据附件；错误目标、旧版本、重复结果给具体提示。只读页面展示核验结论及可追溯依据。主路径在核验通过后进入“保存为方案”的控制面；失败时说明缺少什么，允许回到材料准备，不自动关闭问题。
UI 设计可以表现通过样例，但必须标为示例，不能把“对方说完成”当作通过。

W06 方案库
搜索＋少量筛选＋紧凑内容列表，类型为使用指南、配置方法、工作流方案、修复案例；提示词作为方案中的材料，不再建立重复的大导航。
行内展示用途、适用软件、版本范围、验证状态、最近复核时间。点击进入 W07。列表至少能看出“资料待试用”和“有明确验证证据”的区别；不要凭发布时间判定更可靠。收藏或筛选只改变视图，业务资料编辑进入控制面。

W07 方案详情与保存控制面
主体是一份可读方法：用途、适用条件、准备、步骤、预期结果、验证方法、恢复办法。来源、版本和证据在顶部简洁摘要与展开区。主操作依据场景是“复制使用说明”或“基于此准备材料”。
补充同画板的独立控制面状态：新建／保存方案、编辑生成新修订、查看旧版本。新修订不覆盖旧版。标明材料未验证，或者明确验证发生在哪个软件版本和场景；不把某次修复成功变成对全部环境的保证。

W08 记录
交接、核验、方案修订等历史记录采用一张可搜索时间列表。默认显示用户可理解的事件、关联问题／软件、时间和结果；点开再看证据。记录为同一事实的历史视图，不设计第二个任务管理系统。
日志与诊断默认收起，不首屏铺JSON、哈希或端口列表。更换筛选、进入详情再返回时，保留筛选和阅读位置。

W09 设置与接口
分组为“软件接入、模型服务、显示与浮窗、隐私与数据、接口与诊断”。接口入口在这里和软件详情里都可发现。
区分软件监测／专业适配接口、可选方案助手模型服务、未来跨项目标准接口。只展示真实支持信息；没有连接的接口显示未验证，不生成密钥、余额或成功状态。模型不可用不阻止本地方案查询；常态监测不调用LLM。外部软件订阅只记录用户使用方式，不把订阅权益等同于API已可调用。
保留本地／云端端点、连接状态、支持范围的设计位置，不在设计稿填真实凭据。AAOS 仅在高级说明里可预留合同信息，不出现连接按钮、首页待接入卡或红灯。诊断细节放最后。

W10 独立 HUD：不可遗漏
单独制作440×680桌面浮窗，主窗口外有清楚入口。浮窗不含侧栏，保留“用量／会话／审批”三个标签。
用量展示可确认的Token等事实，成本未知时显示未知，不能把Token、额度、费用混成一数。会话只显示可观察事实。审批展示“需要回到原软件处理”，不在HUD批准。显示最后观测时间、连接／过期状态和打开主窗口的方式。
当前窗口配置并没有实现桌面背景穿透。因此先设计有限玻璃的视觉外壳，不能把设计注释写成已具备原生透明。问题摘要若作扩展，单独标“后续扩展设计”，不替换本阶段三个标签。不放长日志、编辑器和执行按钮。

五、交互与状态规则

请连接核心原型路径：W01→W03→W04→确认记录控制面→W05→保存方案控制面→W07；也要能从W06找到旧方案再回到W04。W02能找到使用方案；W08能回到对应详情；W09能设置HUD；W10能返回主窗口。

Observer／HUD是只读观察面；搜索、筛选、展开、复制和导出派生材料可用。保存业务记录、导入结果、编辑方案属于独立控制面，必须在页面跳转或窗口标题中清楚区分，并保留原对象和返回路径。各控制面可以采用同一视觉模板，不能为每个动作新造一套应用。

请同时设计以下必要状态，采用可复用组件，不为每种状态创建一个新主菜单：首次使用、来源未接入、数据为空、数据过期、断连、核验缺证据、核验失败、保存失败。缺失不是零；断连不是软件停止；工作结束不是项目完成。灰色表达未知／未接入，红色用于有证据的失败，颜色旁保留文字。

加载用静态骨架，不做持续闪烁；过渡120–180ms，尊重减少动效，空闲时不持续动画。长列表分页，初始约20–50行；详情按需加载，媒体不自动播放。设计不要求新增重型图表、3D、粒子或聊天框架。

六、原型示例与完整性

统一使用一套连贯示例：“示例项目·桌面工具”；一个真实感问题为“升级后某项检查无法运行”；描述与版本均标为示例，不虚构用户电脑故障。不展示API密钥、私人聊天正文、编造成本或成功率。未接通和示例状态在设计注释与小型原型标识说明，不在每个页面堆免责声明。

第一阶段仅交付以上10个核心画板＋必要状态／弹层，不扩成几十个后台子系统。主导航数量固定，不为每张画板新增菜单。浅色全套，深色至少展示工作台、方案详情和HUD，其他页面沿用同一套主题变量。
