## 包内主要功能

### 1. “元枢·观心”可视化工作台

启动后访问：

```text
http://127.0.0.1:8010/
```

包含：

- 系统总览和闭环进度；
- 研究包来源、证据、风险与审核；
- 正式知识版本；
- 学习资产审核；
- 5 项确定性指令约束练习；
- 练习次数、质量与掌握度；
- 机器知识候选及权限边界；
- Provider/Model 路由状态；
- Google Research、500 AI 治理资产；
- Job、Outbox 和完整审计时间线。

本次界面是**零前端构建依赖的功能型验收工作台**，不是最终 React 主工作台。这样可以先验证闭环与数据合同，避免前端工程掩盖后端治理问题。

### 2. 人工审核门禁

系统不会自动完成以下晋升：

- Research Candidate → Formal Knowledge；
- Learning Candidate → 可训练资产；
- Mastery → Approved Machine Knowledge。

每次批准、拒绝、要求修改都会生成不可静默覆盖的 `ReviewDecision` 和审计事件。

### 3. 确定性学习验证

吸收了上传交付包中 `instruction_following_eval` 的核心方法，但不执行 Google Research 第三方代码。

内置 5 个本地验证器：

- 必须包含“元枢”；
- 必须恰好有 3 条步骤；
- 总长度不得超过 240 字；
- 必须包含 `review_required=true`；
- 不得出现“自动发布”。

达到掌握度必须满足：

```text
练习次数 ≥ 3
+ 最新质量合格
+ 当前没有未解决错误
```

### 4. Provider/Model 新合同适配

当前仓库新增了 Provider/Model 能力合同，并明确 Dry-run 路由初始为空，不能把未验证模型当成可用能力。fileciteturn6file0L46-L75

本包因此默认设置为：

- `local/deterministic-instruction-validator-v1`：Supported；
- DeepSeek：Candidate、未绑定；
- OpenAI：Planned、未绑定；
- 默认不读取任何 API Key；
- 默认不调用任何云模型。

### 5. Registry V2 对齐

包内注册了两个治理种子：

- `google-research/instruction_following_eval`：`research_only`；
- `500 AI Projects`：`参考/候选Adapter`。

它们都保持 Candidate 和 `requires_human_review=true`，与仓库最新 Registry V2 的治理方向一致。fileciteturn12file0L1-L1

## Windows 启动方法

解压后双击：

```text
START_WINDOWS.bat
```

它会：

1. 在交付包内部创建 `.venv`；
2. 安装最小依赖；
3. 启动 FastAPI 与嵌入式 Worker；
4. 自动打开可视化工作台。

不会修改项目目录外的文件，也不会改写 Cognitive-Loop-OS 现有数据库。
