路径也有 `relative_to(PROJECT_ROOT)` 限制，防止读取项目外文件。fileciteturn14file0L20-L33

工具系统也把 `safe_write` 限制在 `data/output`，`code_exec` 当前直接 blocked，这个安全方向是正确的。fileciteturn13file0L33-L44 fileciteturn13file0L118-L123

# 2. 当前主要问题

## ❗问题1：RAG 还不是真 RAG

现在 `retriever.py` 是从 memory 里做简单词项匹配，`memory/store.py` 也明确写着是 “Simple v1 lexical search; replace with vector DB later”。fileciteturn10file0L32-L42

所以当前不是完整 RAG，只是：

```text
JSONL memory + lexical search
```

下一步必须升级成：

```text
Chunk → Embedding → Vector DB → TopK Retrieval → ContextPack
```

推荐顺序：

```text
sentence-transformers / bge-m3
→ FAISS 或 Chroma
→ 后续再接 Qdrant
```

---

## ❗问题2：Task Compiler 还是占位逻辑

当前 `compile_task()` 固定生成 3 步：

- analyze_context
- plan_next_action
- produce_result

工具都是 `echo`。fileciteturn11file0L6-L19

这对 smoke test 是对的，但对真实系统还不够。下一步要变成：

```text
ContextPack + Route + Risk
→ TaskPack
→ 可执行步骤
→ 工具选择
→ 验收标准
```

---

## ❗问题3：Agent Executor 还只是工具循环

当前执行器做的是遍历 task steps，然后调用 `run_tool()` 并记录结果。方向对，但还不是 Agent。fileciteturn12file0L7-L24

现在它是：

```text
TaskPack executor
```

还不是：

```text
Planner + Tool Router + Reflection + Retry + Eval-aware Agent
```

---

## ❗问题4：Evaluation 太浅

当前 `evaluate()` 基本只看 trace.success，成功就是 1.0，失败就是 0.0。fileciteturn15file0L6-L14

这还不能判断：

- 输出质量
- 是否符合目标
- 是否引用了上下文
- 是否越权
- 是否浪费 token
- 是否应该回流成卡片/经验

下一步要把 eval 拆成至少 5 项：

```text
correctness
safety
trace_completeness
context_usage
next_action_quality
```

---

## ❗问题5：Machine Lesson 有了，但还没有反向影响系统

`compile_lesson()` 会生成 MachineLesson，并写入 lessons。fileciteturn16file0L6-L15

但现在它还没有反过来影响：

- router
- task compiler
- tool selection
- future constraints

也就是说，当前是：

```text
任务 → lesson
```

还不是：

```text
lesson → 下次任务约束
```

这一步是 Cognitive OS 真正进化的关键。
