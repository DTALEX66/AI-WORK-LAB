2. queued 可以直接 claim。
crates/archeaxis-application/src/attempts.rs 的 claim() 接受 queued、failed、cancelled，并在同一事务里登记 attempt 和变为 running。
crates/archeaxis-api/src/runtime/mod.rs 的 start() 当前把 Executor::start 的所有错误统一映射成 409 AAK-CON-003 “job cannot start in its current state”。
因此当前 409 不是“必须先把 queued 迁走”的证明，也不是整条业务请求正确的证明。禁止手动改数据库状态、放宽状态守卫或无差别重试。

src-tauri/src/main.rs 复用了 desktop/src-tauri/src/backend.rs；后者启动的是 python -m app.runtime_entrypoint core。
任务包要求正式 Tauri 接 Rust canonical Core。旧 Python 数据库迁移、browser-smoke 写入和 Python API 成功，只是 legacy 行为证据，不能升级为新架构通过。

四、工程选择按下述实施，不再逐项向 Owner 重问

A. 桌面与目录
复用 frontend/ + src-tauri/ 作为本次正式 Tauri 客户端的候选实现位置；先改接线，不建立第三套壳。
这只是实现位置选择，当前内容仍须通过 Rust 接管验收，productName 和 crate fingerprint 不证明架构正确。
desktop/ 保持恢复/兼容角色。正式壳目前通过 #[path] 使用它的模块，所以不能现在整棵删掉或简单移走。
apps/ArcheAxis.Desktop/ 保留迁移前行为和恢复参考；Tauri 合格接管后退出正式构建入口，转维护冻结。
目录索引按这一角色更新，旧 R6/M0 不改写。将对应 Authority、目录所有权和构建入口的最小 delta 按已有授权落实；机器要求的 issued-envelope/grant 缺失时记录具体缺哪项，准备可审查 patch，不伪造 grant。

B. canonical 数据模型
Rust Core 的 schema/DTO/迁移和提交路径为规范来源。Python evidence_anchors 作为 legacy/worker 输入，用显式适配器映射到 Core，保留无法承载的 locator/来源版本并记录损失。
不双写两套真值，不仅为字段名字另建表。若已有 Core 字段确实不能表达必要定位，给出具体失败样本，扩已有共享合同与 Core 迁移；这是实现缺口，不再把选名字当 Owner 产品决策。
普通原创草稿保存已在 Q04 的范围内，通过 Rust 写入，和正式知识认可分开；不再用旧 W16 “范围未授权”永久阻塞最新重构任务。

C. PRIVATE_NAMES 与依赖暂存
不清空 PRIVATE_NAMES，不给所有 auth/.agents 全局豁免，不用手拷整个 CI venv 代替合格包。
修复两个具体缺口：
(1) 不递归扫描整个 --dep-source 的所有无关安装包；先依据现有锁定依赖解析本切片声明的依赖闭包，只检查实际将被带入的文件。运行时、workers、源/目标根和路径祖先仍保留既有链接/保护检查。
(2) 使用成熟的 Python distribution metadata/RECORD 文件清单，或现有锁文件和已核验 wheel 的离线安装路径，替代“distribution 名等于目录名”的猜测。
对命中的名字区分根位置、来源与文件角色：真实 agent state、凭据、.env、越界路径、junction/symlink 继续拒绝；上游代码中的同名模块只有在确切分发文件归属、内容和哈希核验后才能获局部例外。
“包里有 .agents”不能直接证明安全；“目录叫 auth”也不能直接证明含秘密。
先做 PDF 必要引擎闭包，OCR 再补所需引擎；这是独立能力包的合法范围，但不能把 PDF-only 候选说成完成全量依赖声明。
新增有意义的反例：合法依赖同名模块能暂存；真实私有文件/越界链接仍失败且无半成品；单模块与多模块 distribution 无漏文件；传递依赖缺失明确报错。
手动填过 312 entries、带 6 个 junction 的旧树只保留为开发探针证据，不能改名当合格发行候选。用新的 run 根经修复后的权威暂存器产生干净候选。

D. Windows 工具链
正式 Windows 候选使用 Authority 已登记的 MSVC 工具链和目标 x86_64-pc-windows-msvc。
从登记路径调用，环境限定在当前构建进程，避免全局 PATH/注册表变更；有空格的输出路径问题先用项目允许且当前用户拥有的独立无空格构建目录。
GNU 结果保留为开发证据，不能当正式 MSVC 资格通过。不访问别人的拒绝访问目录，不用 takeown/改 ACL 解决搜索问题。

E. 权限和真人环节
真实库 19 条知识候选逐条处置仍由真人决定。可以准备清单、证据、批注与审核 UI，不能替真人接受或借用 human token。
新桌面写入经正式宿主的有限命令触发；令牌留在宿主。外部探针只使用自己的隔离测试 session，不截取现有桌面令牌，不把 browser-smoke bypass 当生产验收。
一个真人环节不能阻塞 PDF、宿主接线、草稿保存、格式、恢复等独立工程工作。

五、立刻完成的 PDF 切片

先读既有 tests，不重复写状态机说明：
- crates/archeaxis-application/tests/pdf_job_end_to_end.rs
- crates/archeaxis-application/tests/attempts.rs
- crates/archeaxis-api/tests/runtime_jobs.rs
- tests/test_backend_runtime_safety.py
- 既有候选探针的输入、启动和输出契约

用干净、唯一 run_id 的隔离候选及新测试库。固定记录 Core 可执行文件哈希/构建 SHA、worker-profile、解释器、依赖闭包、输入原字节哈希。所有路径取自工具回执/Path/Join-Path，不切字符串，不在仓库根 glob。

最小请求形状（名称与 ID 以真实响应为准，不复制旧 source_id）：
POST /api/v1/imports
  {"name":"document.pdf","content_base64":"<真实原字节的 base64>"}
校验返回 sha256；取返回 source_id。

POST /api/v1/jobs
  {"job_id":"pdf-<唯一run_id>","kind":"pdf","input_ref":"<返回的source_id>"}
注意：该 job kind 是 pdf；pdf.extract 是路由 capability，不是这张 ROUTES 表里的 job kind。

POST /api/v1/jobs/<job_id>/executions
  idempotency-key: exec-<唯一run_id>
  {"deadline_ms":120000}

若仍 409：
1. 一次采集完整请求/响应和状态，不只摘状态码；令牌脱敏。
2. 核对 jobs.kind、来源 original_name 的 .pdf 与 MIME、input_ref、job/request ID、capability 设置、候选 schema/二进制身份。
3. 从 claim 失败的真实错误判断原因。优先在隔离 run 中取脱敏错误；若必须改产品，保留 JobError 的类型并正确映射 404/输入错误/真实状态冲突/存储故障，不再统一报“状态不允许”。不给用户输出内部 SQL、秘密或任意路径。
4. 修请求或修真实代码缺口，复用既有测试并只为新错误分类补必要反例。禁止手工 UPDATE jobs.state。
当前根因尚未确定；“kind 误用”“文件名/MIME 不匹配”等只是检查项，不能预写成事实。

执行接受后有界轮询 GET /api/v1/jobs/<job_id>，直到真实终态，再读 outputs/result、transform 和相关锚点/损失回执。
PASS 必须同时有：正确原件、succeeded、可读且匹配样本的正文、真实引擎身份、有效定位与损失记录、退出重启后同一结果可读。
只完成提取可以记 PDF 提取切片通过，不能记完整产品或全部 PDF 能力通过。
OCR 后续独立验证；不把“无引擎且正确拒绝”升级为 OCR 支持。

保留每次运行的 JSON/日志到自己的 run 目录，机器先从完整文件解析，终端仅输出摘要。最多一次完整复现加一次修复后的验证；若同一前置失败仍未变化，报告具体错误/最小缺口/已准备 patch 并继续可独立任务，不再发一篇新考古文档。

六、PDF 后立即开始真实迁移、合并、删除清理、冻结

迁移：
修改正式 Tauri 的 supervisor/资源布局，使它启动已有 archeaxis-api，沿用 Core launch 契约和实际 bind 0 就绪身份。令牌不进入前端；前端通过有限类型命令读取真实资料与证据。
不要只把 Python app/main 换名字叫 Core。第一验收是实际 Tauri 进程驱动的 Rust Core 生命周期、真实资料列表、退出清理和重启读回。
接着通过已有 Core 接口完成一种原件→阅读定位→引用笔记/草稿保存切片；已有 Document/Block 不足时在 Q04 补最小实现。

合并：
先列具体重复实现及消费者，把可复用的 launcher/DTO/路径解析/worker manifest 逐项收敛到一个实现；恢复壳改为使用共享实现。
合并行为与重复代码，不把恢复能力扔掉，不把 legacy Python writer 合入正式 Rust writer。
本分支与其他 PR 的集成顺序先查实际 diff/owner/dependencies，准备明确集成候选；源码收敛不等于获得合并远端 PR 的授权。

删除清理：
先处理自己本轮创建且确认可再生成的精确临时路径。正式源码的冗余文件只有在消费者归零、替代实现通过、哈希和回滚点可核验后才进入删除清单。
既有目录权威要求受影响路径、owner/data class/consumer scan/rollback/精确删除授权状态；先把清单准备为可审查结果。未获对应授权只停删除动作，继续迁移与测试。
不能用“都不删”逃避清理任务，也不能用“用户说重构”删除未知他人工作树、运行证据、Green/真实资料、共享工具或私有状态。
历史文档的整理不能成为新的连续提交队列，更不能删掉错误撤回与已测 SHA 的审计证据。

冻结：
恢复壳维持必要维护；Tauri 尚未接管前保留 Avalonia 的恢复资格。
新 Tauri 与 Rust、格式及副本恢复通过后，在既有构建/入口登记中明确唯一正式路径，Avalonia 和旧 Python 产品启动面转为行为/迁移参考，停止新增正式功能。
冻结不等于删除源代码或把失败项标 PASS；Release 继续按现有边界冻结。

八、停止空转的执行规则

- 一次读完当前切片的既有测试、当前状态和必要源码，随后修复/运行；不以“还差读一次”拆成连续交接。
