### 1. 我现在最建议你重点研究：OpenViking

它已经不是单纯“记忆库”，官方直接把自己定义成 **Context Database**：

> 一个 Agent 知道的所有东西，都放进同一个上下文文件系统：Knowledge + Memory + Skills。

它甚至用：

`viking://resources/...`  
`viking://user/.../memories/...`  
`viking://user/.../skills/...`

这样的虚拟目录管理上下文。上下文不是黑箱向量，而是可以**查看、修改、搜索、合并、追踪**的。citeturn412641view0

更关键的是，截至目前它已经明确支持：

**Claude / Codex / Cursor / TRAE / OpenClaw / Hermes / OpenCode / DSH / LangChain / 通用 MCP Client**

而且官方已经直接列出了 **DSH Plugin + MCP**、Hermes built-in、Codex Hooks + MCP。citeturn412641view0

这几乎就是你前面一直在找的东西。

它甚至已经有 **Windows x64 Desktop App Beta**，桌面端可以配置本地 Agent 集成、查看 recall/capture 事件，以及同步 Memory 和 Skills。citeturn412641view0

还有一个对你很重要的设计：

**L0 → L1 → L2 上下文分层**

- L0：一句话摘要
- L1：核心概览
- L2：完整内容

Agent 不需要每次把整个项目塞进去，而是先判断相关性，再逐层加载。citeturn412641view0

这对你三个长期项目特别重要，可以明显减少“上下文越堆越大 → Token 爆炸 → 模型开始漂移”的问题。

### 2. 但如果你说的是“所有软件统一入口”，还要加 IBM ContextForge

这个和 OpenViking不是竞争关系。

**OpenViking负责：**

> AI 应该知道什么。

**ContextForge负责：**

> 哪个 AI、哪个软件，在什么情况下，可以访问哪些上下文、工具、Agent 和 API。

IBM ContextForge 现在可以把：

**MCP + A2A + REST + gRPC + Agent**

统一到一个 Gateway 后面，并提供统一 registry、权限、认证、限流、日志、OpenTelemetry tracing、Admin UI。citeturn552052search0turn552052search3

所以真正适合 WORK-LAB 的结构其实是：

```text
ChatGPT / Codex / Hermes / DSH / Claude
Cursor / OpenCode / 其他 Agent
                 │
                 ▼
        ┌─────────────────┐
        │   WORK-LAB      │
        │ Context Control │

        IBM ContextForge
        Gateway / Registry
                 │
        ┌────────┴────────┐
        │ Context Router  │
        │ Policy / Scope  │
```

我认为这比“再做一个知识库”重要得多。

### 3. Supermemory：最适合先快速试验

如果你不想现在就搭完整架构，**Supermemory 是目前非常接近“一装就能跨软件共享记忆”的方案**。

它官方直接支持：

**Claude Code、Cursor、Codex、OpenCode、OpenClaw、Hermes** 等插件，并且提供统一 MCP Server。citeturn960859view1

它会自动处理：

- memory
- recall
- project context
- user profile
- recent activity
- contradictions
- expired information
- RAG
- Gmail / Drive / Notion / OneDrive / GitHub connectors

citeturn960859view1

所以例如：

```text
今天 Codex 得出：
AAOS 数据目录固定在 D:\xxx

↓

写入 Supermemory

↓

明天 Hermes：
“AAOS 在哪里？”

↓

直接 recall 出来
```

不用每个软件重复告诉一次。

如果只是验证“跨 Agent 共享记忆到底值不值得做”，它比你直接改 WORK-LAB 快很多。

---

### 4. Mem0 更像“记忆引擎”

Mem0 已经支持区分：

**User Memory / Session Memory / Agent Memory**

并支持自托管 Server、Cloud、CLI、SDK。citeturn412641view1

它甚至提供过浏览器扩展，可在 ChatGPT、Claude、Perplexity 等之间共享记忆。citeturn412641view1

但它更偏：

> Memory Infrastructure

而不是你需要的：

> Project Context Operating System

所以我会把 Mem0 当 **可吸收模块**，而不是 WORK-LAB 的整体底座。

---

### 5. Graphiti 特别适合解决你一直遇到的“上下文过期”

例如项目历史：

```text
2026-08
DSH 安装在 C:\xxx

2026-09
正式迁移 D:\All projects\DSH

现在
必须以 D:\All projects\DSH 为准
```

普通 RAG 很可能三个都搜出来。

Graphiti 的核心是 **Temporal Context Graph**，每个事实可以保存：

```text
事实
来源
建立时间
有效时间
何时失效
被什么事实替代
```

它专门处理“现在什么是真的、以前什么是真的”，同时保留 provenance。citeturn960859view3

所以非常适合你的：

- 安装路径
- 当前版本
- 权威文档
- 项目决策
- 已完成/废弃任务
- 架构迁移
- 工具替换

但没必要单独拿它做整个系统。

## 所以我现在对 WORK-LAB 的判断已经更明确了

你前面一直说的：

> 怎么防止上下文丢失、失忆、幻觉、漂移、外置库路径找不到、没有先搜索就自己下载工具、不同 Agent 重复做工作。

**本质上不是“Memory 问题”。**

是一个完整的：

**Context Governance / Context Control Plane 问题。**

因此 WORK-LAB 应该增加一个真正的一级模块：

### `Context Control Plane`

内部至少管理：

```text
01 Project Identity
02 Canonical Facts
03 Context Manifest
04 Decision Ledger
05 Task State
06 Session History
07 Path Registry
08 Tool Registry
09 Skill Registry
10 Dependency Registry
11 Source / Provenance
12 Memory
13 Knowledge
14 Permissions
15 Context Expiration
16 Conflict Resolution
17 Context Routing
18 Context Compression
19 Agent Handoff
20 Audit Trail
```

然后规定：

```text
任何 Agent 开工
        ↓
读取 PROJECT_MANIFEST
        ↓
读取 Current State
        ↓
查询 Context DB
        ↓
查询 Tool Registry
        ↓
查询 Path Registry
        ↓
查询 Decision Ledger
        ↓
确认已有工具
        ↓
确认已有实现
        ↓
才允许下载 / 修改 / 新建
```

这样 Codex 换 Hermes，Hermes 换 DSH，甚至换模型，**“脑子”都没有换**。

Agent 只是执行器。

真正的项目记忆属于：

> **WORK-LAB Context Layer**

而不是属于某一个 AI。

### 我目前最看好的组合

**不要重新从零造。**

直接研究：

**OpenViking + IBM ContextForge + Git + Graphiti（可选）**

其中：

**OpenViking = Context Brain**  
**ContextForge = Context Gateway**  
**Git = 权威事实/版本证据**  
**Graphiti = 时间事实与关系图**  
**WORK-LAB = 治理与控制层**

而 **Supermemory / Mem0** 可以拿来做对照实验、吸收 Memory Pipeline。

这套方向比单纯再做一个“记忆功能”要高一个层级，而且和你现在 WORK-LAB 的定位高度吻合。memcite
