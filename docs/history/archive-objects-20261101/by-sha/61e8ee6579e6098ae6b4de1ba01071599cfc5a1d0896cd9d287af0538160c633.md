# DeepSeek Harness（DSH）开源简报

> 发布时间：2026‑08‑13，v0.1 开发者预览版，**MIT 协议开源36氪**
>
>  GitHub：[https://github.com/deepseek](https://github.com/deepseek "autolink")‑ai/deepseek‑harness
>
>  NPM 包：`@deepseek‑ai/dsh`

## 它是什么

它**不是新大模型**，是一套**Agent 智能体运行底座**（harness 本意马具 / 缰绳），公式：**Agent = Model + HarnessDeepSeek**。

 大模型负责思考推理；Harness 负责对接文件系统、终端、浏览器、工具调用、任务调度、会话管理、沙箱权限、长任务断点续跑，把模型变成能在本机真实干活的 AI 智能体，主打 Vibe Coding 沉浸式 AI 编码开发**36氪**。

### 核心设计：一切皆插件 Everything is a plugin抖音百科

基于 Cordis 内核：模型适配器、工具、技能、会话日志、沙箱、存储、Agent 循环、UI 全部是插件，**不用改源码，配置即可替换 / 扩展**，兼容各家主流大模型，不强制绑定 DeepSeek 自家模型。

## 快速本地启动

前提：本机安装 Node.js

bash

```
# 直接npx拉起web界面
npx @deepseek-ai/dsh web

```

访问：`http://127.0.0.1:3080`，即可打开本地 WebUI**GitHub**。

源码编译部署：

bash

```
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web

```

## 四大运行模式

1. **标准模式**：完整工具集，日常编码开发
2. **PCT 模式**：程序化工具调用，模型生成代码编排多轮工具
3. **极简模式**：轻量，去掉复杂沙箱，适合简单任务
4. **创造模式**：用 Harness 来开发新插件

## 关键特性

- 会话日志**只追加存储**，完整可追溯，上下文压缩不会抹除原始历史记录**抖音百科**
- 沙箱权限管控，高危操作人工确认
- 支持长任务、多 Agent 编排、断点续传
- 内置大量官方插件，社区可自由开发分享插件
- 现阶段为开发者预览版，后续版本会存在破坏性变更，不建议直接上生产环境

## 对标定位

对标 Claude Code、OpenAI Codex，是国产面向 Vibe Coding 场景的开源 Agent 底座，目标争夺 Agent 基础设施生态，让开发者自由组装属于自己的 AI 开发智能体**36氪**。   这个对我三个主要项目有帮助吗？

# AijiuOPC AI 原生桌面工作台｜界面深度拆解

> 视频作品：VibeCoding 大赏作品，AI 原生桌面工作台，包含**AI 员工、AI 浏览器、真实终端、全球热点、数据大屏、全局多 Tab 工作台**，属于 Tauri/Electron 混合式 AI‑Agent 桌面应用，不是纯网页 Demo，是持续迭代的个人 AI 操作中枢**GitHub**。

> 注意：该项目未公开完整源码，下面是基于同类前沿开源项目（marudesk、cc‑desk、hermes‑web）结合视频 UI 表现做逆向技术还原，全部是当前 VibeCoding 做同类工作台的标准工程方案**GitHub**。

## 整体架构选型（界面底层）

**两种主流路线，AijiuOPC 大概率是 Tauri v2 + React + TS + Vite**（体积更小、安全，现在 AI 桌面工作台首选），备选 Electron。

- 后端：Rust (Tauri)，负责系统能力调用：真实终端、文件读写、系统窗口、本地存储、沙箱隔离
- 前端：React19 + TypeScript + TailwindCSS，负责全部 UI 渲染、Tab 布局、组件、动画
- 状态管理：Zustand，管理多 Tab 实例、Agent 会话、终端实例、浏览器实例全局状态
- 本地存储：SQLite，持久保存 tab 布局、会话记录、工作台布局配置

> 整体模式：**Web 前端渲染界面，Rust 后端桥接真实系统能力**，界面长得像网页，但可以调用本机真实终端、真实浏览器内核。

## 一、核心难点：全局多 Tab 可拖拽工作台界面

视频最直观特征：可以新建无数 Tab，每个 Tab 可以承载不同组件：AI 员工聊天、终端、浏览器、数据大屏，Tab 可以拖拽排序、关闭、拆分面板。

### 技术实现库：`dockview`

> 现在几乎所有 AI Agent 工作台（hermes‑web、cc‑desk）都在用 dockview，专门做 VSCode 风格可拖拽 Dock 标签面板布局**GitHub**。

1. Dockview 核心能力 
   - 多 tab 分组、拖拽移动 tab、拆分左右 / 上下分栏、浮动面板
   - 每个 tab 绑定一个独立组件实例（Terminal 组件 / Browser 组件 / Chat 组件 / Dashboard 大屏组件）
   - 布局状态序列化保存到本地，重启工作台自动恢复上次布局
2. 界面分层

plaintext

```
└──主窗口（Tauri窗口）
    └── Dockview容器（全局工作台）
        ├─ Tab1：AI员工聊天面板
        ├─ Tab2：真实终端面板
        ├─ Tab3：AI内置浏览器面板
        └─ Tab4：数据大屏面板

```

> 不是浏览器原生 tab，是应用内部自定义 tab 系统；每个 tab 内部组件完全隔离，实例独立，切换 tab 不会销毁状态，终端不会断连。

## 二、各个功能模块界面实现细节

### 1. AI 员工面板（多 Agent 聊天界面）

UI 特征：多角色 AI 员工卡片、流式输出、工具调用卡片、思考过程折叠、消息分组。

- Markdown 渲染：`react‑markdown` + shiki 代码高亮，渲染 AI 输出代码块、表格
- 流式渲染：前端 SSE/WebSocket 逐块接收模型输出，增量渲染，不需要等待完整返回
- Agent 工具调用 UI：自定义卡片组件，展示调用工具、参数、返回结果，折叠 / 展开详情
- 多员工状态：Zustand 维护多个 Agent 实例，每个员工独立会话上下文，互不干扰

### 2. 真实终端面板（不是网页模拟终端）

> 关键点：不是前端模拟假终端，是真正本机 shell，视频里可以执行真实系统命令。

1. 底层 
   - Tauri 后端调用 **`portable‑pty`**（跨平台伪终端），启动真实系统 bash/powershell，拿到 pty 句柄
   - 前端组件：`xterm.js`，渲染终端 UI 界面，接收 pty 输出流，把用户键盘输入转发给 pty 后端**GitHub**
2. 数据流：

plaintext

```
键盘输入 → xterm.js前端 → Tauri Rust后端 → portable‑pty真实系统shell → 命令输出流 → xterm渲染界面

```

- 每个 Tab 的终端都是独立 pty 进程，互不干扰；关闭 tab 同时销毁后端终端进程。

### 3. AI 浏览器面板（内置真实浏览器）

> 不是 iframe！可以真实访问网页，Agent 可以读取 DOM、网络请求，操作网页。
>
>  两种实现方案：

1. Tauri 方案：直接嵌入 Tauri Webview，每个 tab 创建独立 webview 实例，通过 CDP（Chrome DevTools Protocol）控制网页，Agent 获取页面 DOM、截图、执行 JS。
2. Electron 方案：BrowserView 嵌入窗口。

> 区别普通 iframe：iframe 有跨域限制；内置 webview 是完整独立浏览器内核，可以任意跨域，Agent 可以操控网页。

### 4. 数据大屏 & 全球热点面板

- 图表库：`Recharts` / `ECharts`，做大屏可视化面板
- 热点数据：前端请求外部新闻 API，数据做格式化，渲染卡片 / 图表
- 大屏支持 dockview 嵌入 tab，支持缩放、分栏，和终端、聊天面板并排摆放。

## 三、视觉 & 交互设计（UI 层面）

1. 风格：深色液态磨砂 UI，苹果液态风格，大量毛玻璃、圆角、弱渐变阴影 
   - Tailwind 自定义主题，配合 `framer‑motion` 做面板动画、tab 切换过渡、弹窗动画
2. 窗口组件全部是组件化：Chat、Terminal、Browser、Dashboard 全部为独立 React 组件，**可以被 dockview 随意挂载到任意 Tab / 分栏**，这就是 “AI 原生工作台” 的核心：所有模块都是可插拔瓦片 Tile，自由组合布局。

## 四、VibeCoding 开发这套界面的工作流（作者开发方式）

## 六、关键坑点（同类项目踩坑）

1. dockview 实例管理：每个 tab 销毁的时候，必须同步销毁后端 pty 终端 /webview 实例，否则后台进程泄漏。
2. 终端流处理：pty 输出是二进制流，前后端消息转发要做节流，不然前端卡顿。
3. webview 隔离：每个浏览器 tab 独立 webview 实例，避免 cookie、上下文互相污染。
4. 布局持久化：dockview 布局 JSON 序列化存入 sqlite，重启恢复工作台布局。  看看这个，深度挖掘实现的可能性，针对我的系统项目和工作流项目
